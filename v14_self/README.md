# V14 自举编译器 · 全链（甲言的起点）

> **这是甲言血缘链条的第一环。**
> 2026-07-13/14 完成，是整个项目**第一个能自己编译自己的编译器**。
> 本目录把它连同可执行文件一起放在这里，是为了让「主源从哪来」这件事**在仓库里可查、可跑、可验** —— 而不只是文档里的一句话。

## 一、这是什么

| 项 | 值 |
|:--|:--|
| 文件 | `cpu64_v14_self.c`（**723 行** / 34,071 B）+ `cpu64_v14_self.exe`（96,750 B） |
| 完成时间 | **2026-07-13 / 07-14** |
| 编码 | **GBK**（原文如此，为保留原件未转码） |
| 源码 SHA256 | `C638FF62822587F7…` |
| 可执行 SHA256 | `0054F207B7637FC5…` |
| 依赖 | **零** —— 不需要 gcc、不需要 Python、不需要任何运行时 |

**它自己就是一套完整的工具链**：单文件里包含 VM + 汇编器 + 自举 C 编译器 + JSON 脉冲输出。

**源码头部自述的五条公理**（原文，GBK 直接读取）：

```
A1: 零依赖自举 —— 单文件 VM + 汇编器 + 自举 C 编译器
A2: 28 指令精简集 —— 5-bit op，两字指令全在 0-31
A3: ENC(5+3+8) 编码 —— 5-bit op + 3-bit rd + 8-bit val
A4: 批量推演协议 —— --batch 输出 engine_loop 可消费的 JSON 脉冲
A5: 自举 C 子集 —— int / 赋值 / 加减 / if / while / 函数 / 参数
```

## 二、怎么验（一条命令，不需要装任何东西）

```bash
# Windows
v14_self\cpu64_v14_self.exe

# 或在任意 cwd 下用绝对路径
C:\path\to\repo\v14_self\cpu64_v14_self.exe
```

**不需要参数**。默认行为 = 自举测试 + 铁律检查。

### 2026-10-25 实测输出（原件原样）

```
v14_self —— 自举+JSON脉冲
seed=828 | 宇和·启元

[self_compile] 自举编译器测试
[self_compile] asm=341指令
[self_compile] r0=42 (expect 42) PASS
[???] r0=1 (expect 1) PC=323 PASS

done
```

**退出码 `rc=0`。**

一行 `PASS` 意味着：**它编译了自己，然后跑起来，算出了预期结果。**
这不是"能启动"，是**自举闭环成立**。

## 三、它在血缘里的位置

```
① V14 自举编译器（本目录）         2026-07-13/14   723 行      ← 你在这里
        ↓ 从 28 指令 VM 走向真实 x86-64 目标

        ↓ 甲言入仓

        ↓ 机械汉化
④ 汉化镜像（srclib_jiayan/qcc_work.jy）             22,571 行
        ↓ 持续手工演进（+12,627 行）
⑤ 主源（srclib_jiayan/qcc_zh.jy）  至今          35,264 行   ← 现在的甲言
```

**我们继承的是这条链，不是从零重新发明。**
所以对外一律说「**中文书写**」，不说「中文原生」—— 后者容易被理解成"从零为中文设计"，那不是事实。

**但"自举"这件事从第一天就在**：V14 本身就是自举编译器。

## 四、为什么把它放进仓库

| 理由 | 说明 |
|:--|:--|
| **来路可查** | 血缘表不再是文档里的一段话，而是目录里能点开、能运行的实物 |
| **第一环可复现** | 任何人可以下载、双击、看到 `PASS` —— 不需要相信我们的描述 |
| **可对照演进** | 723 行 → 35,264 行的差距，是**公开可见的增长**，不是宣称 |
| **原件保真** | GBK 编码原样保留、SHA256 记录在案，**没有为了好看而修饰** |
