# A9010 被调者不是函数指针

> 错误码 | 调用/被调者语义 (A9xxx) | 新增 2026-10-03 (第 455 站第二十三轮 · L-15 真接入)

## 触发场景

函数调用的**被调者**表达式不是「指向函数的指针」(C11 6.5.2.2)。甲言在**编译期**拒绝，
而不是像修复前那样静默产码、运行期 `0xC0000005`。

两类触发：

| 形态 | 例子 | 为什么非法 |
|:--|:--|:--|
| `&` 取址 | `整 (*fp)(整) = 加一; (&fp)(5);` | `&fp` 的类型是 `int (**)(int)`（二级），不是函数指针 |
| `*` 解引用 | `整 *p = &甲; (*p)(5);` | `*p` 是 `整`，不是函数指针 |
| `*` 解引用 | `整 (***ppp)(整) = &pp; (*ppp)(5);` | `*ppp` 的层级是 1，仍不是「层级 0 的函数指针」 |

## 语法（甲言）

```c
整 加一(整 x) { 返 x + 1; }

函数 整 主(空) {
    整 (*fp)(整) = 加一;
    整 甲 = (&fp)(5);        /* A9010: `&fp` 是 int(**)(int) */
    返 0;
}
```

## 修复建议

- 调**函数名**：直接写 `加一(5)`；若要显式取址，写 `(&加一)(5)`（合法，等价 `加一(5)`）。
- 调**函数指针变量**：写 `fp(5)`，或解引用一代表达「这就是函数指针」写 `(*fp)(5)`。
- 调**多级指针**：只解一层——`整 (**pp)(整) = &fp; (*pp)(5);` 合法；`(**pp)(5);` 也合法（C 规则：函数指示符立即退化）。
- 数据指针（如 `整 *p`）**永远不能**当函数调用。

## 说明

合法面（本仓已钉正锚）：

| 形态 | 判定 | 依据 |
|:--|:--|:--|
| `加一(5)` | ✅ | 直接调用 |
| `(&加一)(5)` | ✅ 归一化为 `加一(5)` | `&函数名` 的类型正是函数指针 |
| `fp(5)` / `(*fp)(5)` | ✅ | `fp` 层级 0；`*fp` 是函数指示符，丢掉那一层 |
| `(*pp)(5)` | ✅ 真解引用一次 | `pp` 层级 1，`*pp` 才是函数指针 |
| `(**pp)(5)` | ✅ | 内层 `*pp` 已是层级 0 |
| `(&fp)(5)` / `(*p)(5)` / `(*ppp)(5)` | ❌ A9010 | 上述表 |

判据来自**声明期登记的 A22 基类码**（`变量指基`，基类 9 = 函数指，层级 = `码 / 16`），
不是从节点形状猜——形状与语义之间的差正是崩溃的藏身处。
管道 `|>` 用**同一判据**决定右操作数是否放行，故直接调用与本锚的判定恒一致（矩阵 0 mismatch）。
