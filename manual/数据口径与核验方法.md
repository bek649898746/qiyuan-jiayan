## 三、⚠️ 无法直接核验的（诚实标注，不包装成已验证）

| 宣称 | 为什么核验不了 | 我们提供什么 |
|:--|:--|:--|
| **Git 2.45.2 全量编译（563 个 C 文件）** | git 源码属**第三方版权，不随仓库分发** ⟹ 无法**直接**核验 | **但已独立复验**：2026-10-15 用本项目自举产物跑官方闸，得 **540 通过 / 23 失败 / 0 崩溃**，与项目记录**逐数一致**；17 处适配清单见 [`GIT_RUN_ADAPTATIONS.md`](../GIT_RUN_ADAPTATIONS.md) |
| **zlib / Lua 语料全绿** | 语料不随仓库分发 | 可用脚本复现；语料自备 |
| **tests/compiler 产物（391 asm + 107 c）** | 不入仓库（「存种子不存果实」原则） | 运行 `scripts/verify_all.ps1` 重新生成 |
| **不动点哈希的具体数值** | **源码每次合法修改都会改变它** | 判据改为「**连续代哈希全等**」，脚本内 `$expected` 仅作记录 |
| **多语言实现（九线）· 329 用例 / 326 通过** | 逐例源码与九线合并总账属**内部审计档案**（`_audit_inbox/`），按上传纪律**不随仓库分发** ⟹ **无法直接核验**（2026-10-17 审计实测：仓库内仅 2 份文档，无 `.jy` 源码与用例） | 提供 [`manual/多语言实现.md`](多语言实现.md) —— 含验收口径与**局限**的完整标注（如"不需要官方 JDK/Go/Rust 工具链"这一局限的来源） |

## 四、我们的口径原则（三条）

1. **判据优先于数字** —— 自举用「**连续代哈希全等**」，而不是比对写死的期望值。
   （2026-10-15 实测教训：脚本里的 `$expected` 曾滞后 44 天，导致**任何用户 clone 后照文档跑都看到假 FAIL 并当场中断**，而自举其实完全成功。）
2. **不写死会变的数字** —— 行数 / 通过数 / 体积等凡随源码演进者，一律注明「**以脚本实测为准**」。
3. **不能核验就明说** —— 不把无法核验的东西包装成已验证结论；能提供替代证据的（如适配清单）就提供。
