## 一、总原则：跨线复用的是「**骨架**」，不是代码

> 九线中最后一线的原话：
> **跨语言线复用的不是"代码"，而是「一套已经跑通的骨架」**
> —— 槽模型 / 调用协议 / 类表 / 函数表 / 坑回填。

**证据 = 承接链上的「拦错曲线」**（同一套骨架沿链传递后，编译器拦下的写法错误急剧下降）：

```
JS → JV → Java → Python → Go → Rust → TypeScript → C++ → C#
```

| 线 | 承接自 | 编译器拦下的写法错误 |
|:--|:--|--:|
| Java | 起手 | **10 次** |
| Python | 承接 Java | 1 次 |
| Go | 承接 Python | **0 次** |
| Rust | 承接 Go | **0 次** |
| TypeScript | 承接 Rust | **0 次** |
| C++ | 承接 TS | 4 次（**均为我方写法问题，非编译器拦错**） |
| C# | 承接 C++ | 2 次 |

**下降的两个原因**：
1. **开工前先建「关键字 / 内建 黑名单」** —— 这张表是在 Java 的 10 次、Python 的 1 次之后才总结出来的；
2. **骨架复用**（上表后五线的核心变量）。

> ⚠️ **但黑名单挡不住全部**：它只防"保留词"，**防不住「位置相关的漏检」**
> ⟹ 末两线最终仍靠**探针 + 打印中间产物**把问题逼出来。

## 二、19 条可复用手法（按语言出处）

| # | 手法 | 出处 | 一句话 |
|--:|:--|:--|:--|
| 1 | **`#` 前缀隐藏槽** | Python · Go | 内部槽名以 `#` 开头 ⟹ **与用户标识符永不相交，无需转义** |
| 2 | **两阶段回填** | Python（踩坑）→ 其余五线（受益） | **先编完所有函数体，再统一回填调用坑** |
| 3 | **缩进 token 按「种」吃** | Python | INDENT 的值 = 缩进列数（不固定）⟹ 只能 `吃种(...)`；DEDENT 的值才恒为 0 |
| 4 | **`for` 三子句：源码序 ≠ 执行序** | Go | `初 \| 环首:条 \| 假跳出口 \| 跳体 \| 增处:增 \| 跳环首 \| 体:体 \| 跳增处 \| 出口:` |
| 5 | **`struct` 槽段表示法** | Go | 结构体占**连续槽**：基槽存类型号，字段在 `基槽+1+偏移` |
| 6 | **`if` 是表达式（两分支各压一值）** | Rust | `let y = if c {10} else {20};` ⟹ 判定→假跳→压 10→跳汇合→压 20→汇合后取值 |
| 7 | **尾表达式即返回值** | Rust | 直接把「值块」当函数体，末尾接 `RET` ⟹ **分层推进的红利** |
| 8 | **`impl` + `&self` 的间接寻址** | Rust | `self` 槽存**接收者基槽号**；`self.x` ⟹ 间接读 `值区[基槽 + (1+偏移)]` |
| 9 | **类型表即判据** | TypeScript | 每例打印「变量 → 类型」⟹ **"通过"不是碰巧** |
| 10 | **编译期类型检查 = 不生成码** | TypeScript | `x:number` 却写 `if (x)` ⟹ **字节码里该块未生成**（判据可见） |
| 11 | **`<<` 双重身份靠上下文标志** | C++ | 流插入 vs 左移；**标志的作用域必须与语法结构对齐** |
| 12 | **重载分家靠「先编实参 + 记类型」** | C++ | `CALL` 本就发射在实参之后 ⟹ 编实参 → 记类型 → 找重载 → 最后补 `CALL` 序号 |
| 13 | **RAII 靠 `入块()`/`出块()` 对象表** | C++ | 块退出时**逆序**发析构 `CALL` |
| 14 | **`new` 的两个语境分别写死语法形状** | C# | 对象构造 `new V(3)`（带括号）vs 数组创建 `new int[3]`（无括号） |
| 15 | **数组 = 一段连续槽（与对象字段同构）** | C# | 基槽存长度、元素紧随其后 ⟹ **数组变量与数组形参走同一套寻址**（`params` 打通的关键） |
| 16 | **`foreach` 降解为 `while`** | C# | 复用发坑/填坑/发跳；**★ 环首只能包住「条件＋体＋步进」，初始化式必须在环外** |
| 17 | **属性访问器模式** | C# | getter/setter 走对象槽派发；setter 的隐式 `value` **紧跟 `this` 分配槽**以保形参连续 |
| 18 | **委托 = 函数序号 + 间接调用** | C# | **复用整套调用/返回协议，不另造一套** |
| 19 | **跨线复用的是骨架，不是代码** | C# | 槽模型 / 调用协议 / 类表 / 函数表 / 坑回填 |

## 三、指令集层面的跨线累积

新语言的实现往往只**新增少量指令**，其余复用既有协议：

| 指令 | 语义 | 首次引入（因哪条线） | 被谁复用 |
|:--|:--|:--|:--|
| **间接读 / 间接写** | `值区[值区[N]+M]` | **Rust（`impl` + `&self`）** | C# 数组长度 · `ref`/`out` 读写 |
| **对象槽派发** | 运行期按实类找成员 | C++ / C# | 属性访问器派发 |
| **段复制** | 区间搬移 | C++ | — |
| **数组读 / 写** | 带边界语义 | **C#** | — |
| **间接调用** | 序在实参之下 | **C#（委托 `delegate`）** | — |

> **设计要点**：新增的「间接调用」**复用了既有调用/返回协议的整套机制（含旧形参保存恢复）**，
> **没有另造一套** ⟹ 委托只多加了"序"这一层间接。

## 四、三条方法论教训（★ 比手法本身更值钱）

### 4.1 「碰巧通过」不是通过（三线各一次实证）

| 线 | 曾长期绿着的假象 | 加什么对照才戳穿 |
|:--|:--|:--|
| C# | 数组用例**因为数组恰好占用槽 0** 而一直绿 | 加「数组不在槽 0」的对照 ⟹ 立刻暴露（基槽号未初始化恒 0） |
| C# | 多态用例因「槽 0 恰好是那个对象」而蒙对 | 加两组对照 ⟹ 因此**修正了对象赋值语义** |
| C++ | 继承用例 7/8 通过，唯一失败是成员初始化列表 | — |

**⟹ 规则**：用例全绿时，要问一句「**它是真的对，还是恰好对？**」
——**改变无关条件（槽号、顺序、命名）再跑一次**，是最省事的证伪手段。

### 4.2 诊断本身用到的工具，必须先被验证

C# 线曾据「函数表打印异常」判定某类型表坏了，
加了调试打印后发现**类型表完全正确**，坏的其实是**诊断所依赖的那个查表函数**。

**⟹ 规则**：**你用来诊断的工具，要先被独立验证一遍**，否则会把"工具的错"当成"被诊对象的错"。

### 4.3 负证据也是证据

**「看不到输出」≠「没有输出」** —— **先怀疑过滤器，再怀疑程序**。

## 五、流程铁律（6 条 · 可直接执行）

1. **每一轮先备份，且先投递** —— 曾**两次**靠留底整体回滚救回。
2. **删块时不许凭记忆数行数** —— 曾按 20 行删、实际 15 行 ⟹ 括号不匹配。
   正解：用**插入文本作精确字面量**，或**打印块首/块尾行**确认。
3. **改文件一律用 `ReadAllText`/`WriteAllText` ＋ `IndexOf`/`Substring`** ——
   源文件是 **LF only**，CRLF 锚定的 `Replace` 会**静默失配**；`WriteAllLines` 会改行尾（甲言对行尾敏感）。
4. **`.NET` 静态方法用进程工作目录，不认 shell 的 `cd`** ⟹ **一律传绝对路径**。
5. **工作目录必须纯 ASCII** —— 编译器拒绝中文路径参数。
6. **括号配平会把字符串字面量里的 `[`/`]` 也计进去** ⟹ 格式化串里不要写 `[`/`]`；
   **先把值落到局部变量再打印**。
