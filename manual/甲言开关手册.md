## 一 · 30 秒上手（90% 的人只需要这 5 个）

```powershell
# 1) 编译成 exe（最常用）
.\qcc_zh_seed.exe hello.c -o hello.exe

# 2) 只编译不链接（产 .obj / .o）
.\qcc_zh_seed.exe -c util.c -o util.obj

# 3) 编译 Linux 可执行（需 WSL 或真 Linux 环境）
.\qcc_zh_seed.exe hello.c --target=elf -o hello

# 4) 找不到运行库时（换目录使用 / 只拷了 exe）
$env:QCC_RT_PATH = 'C:\path\to\qcc_rt.c'

# 5) 觉得产物太大，想回退到"全量运行库"
$env:QCC_NO_DCE = '1'      # 20,992 B → 385,536 B
```

## 二 · 命令行参数（27 个）

### A. 编译产出类（改产物）

| 参数 | 作用 | 默认 | 备注 |
|:--|:--|:--|:--|
| `-o <out>` | 输出文件路径 | 由输入推导 | — |
| `-c` | 只编译到目标文件，不链接 | 关 | 产 COFF `.obj`（PE）/ `ET_REL`（ELF）|
| `-S` | 只到汇编文本 | 关 | 产 `.asm`（约 45 万字节/主源）|
| `-g` | 生成 DWARF 调试信息 | 关 | #289 · 行号/文件归属/行表 |
| `-bin` | 裸二进制（内核用） | 关 | 不加 PE/ELF 容器头 |
| `--target=elf` / `--target elf` | 目标 Linux ELF64 | PE | 与 PE 同布局，各有一个不动点 |
| `-I <header>` | 预包含头文件 | — | 等价 GCC `-include` |
| `-D <名=值>` / `-D名=值` | 定义宏 | — | 两种写法都认 |
| `--lenient` | 兼容档：放宽 A9002 显式转换 | 关 | 迁移旧 C 代码时用 |

### B. 观测 / 导出类（**不改产物**）

| 参数 | 作用 | 备注 |
|:--|:--|:--|
| `-graph <out.json>` | **代码知识图谱**（编译完旁路导出） | AI 查询代码结构的主入口，10 条查询 |
| `--interface` | 接口/语义导航（API 表面 + 函数定义行号） | 让 AI「读接口不读实现」 |
| `--refs [out.json]` | 引用收集（谁引用了 X，名+行） | 反查影响面 |
| `--annotations` | 注解导出 | 元数据标注可观测 |
| `--dag [out.json]` | 编译 DAG 重放证明（阶段哈希链） | 可复现性证明 |
| `--budget` | 编译期资源水位报告 | 内存/耗时 |
| `--profile` | 编译剖面 v3（阶段/规模/诊断/八热点/工作集） | 默认关 ⟹ 零输出、产物不变 |
| `--checkpoint <path>` | 编译检查点 / 崩溃尸检 | 崩溃后能看进度快照 |
| `--recorder <path>` | 编译黑匣子 | 飞行记录 |
| `--selfcheck <sha256>` | 产物哈希对账不动点（别名 `--自检`） | 验「编出来的就是那个」 |
| `--repeat <N>` | 同进程连续编译 N 次（可重入验证，别名 `--重复`） | 查状态残留 |
| `--ir` / `--dump-ir` | 导出 IR L1 抽象指令 + 子指令链 | 等价 `QCC_DUMP=ir` |
| `--ir-only` | **只建 IR + dump，不写产物**（产物写向 NUL） | S0-1；不可用于出成品 |
| `--cache` | 文件级哈希增量编译 | sidecar 式，命中跳过编译 |
| `--cache-verify` | 增量 + 命中时新鲜编译对账复验 | 增量结果纳入不动点链 |
| `--serve` | 编译服务器（长驻 输入流/输出流） | 迭代循环毫秒级 |
| `--dj` / `--diagnostics=json` | **结构化诊断**（`{代码, severity, 消息}`） | 给 AI 消费的主要接口 |
| `--test` | 自检 | 秒回 |
| `--help` | 帮助 | 参数清单在这 |

## 三 · 环境变量（48 个）

### A. 真正影响产物的（**只有 3 个**）

| 变量 | 作用 | 默认 | 实测效果 |
|:--|:--|:--|:--|
| **`QCC_NO_DCE=1`** | 关闭运行库裁剪（回全量） | 裁剪**开** | 最小程序 **20,992 → 385,536 B** |
| **`QCC_RT_PATH=<路径>`** | 指定 `qcc_rt.c` 位置 | 自动找（cwd / exe 目录）| 找不到时编译**响亮失败**，不产坏产物 |
| `QCC_OPT=<档>` | 优化档（如 `none`） | 默认档 | `QCC_OPT=none` 关常量折叠 |

### B. ⚠️ **幽灵开关：设了没有任何作用**（3 个，实测确认）

| 变量 | 为什么没用 |
|:--|:--|
| **`QCC_SMALL_HEAP`** | **分支已删**（R896 2026-11-04 根治）。全仓只剩注释，`取环境()` 零命中。它原本也只是「构建期旋钮」，从来不是运行期开关 |
| **`QCC_RT_DCE=1`** | 文本级裁剪开关，但**链接期裁入已默认开且裁得更彻底** ⟹ 实测产物与默认完全相同（20,992 B），**没有任何额外效果** |
| `QCC_DCE_NOSKIP=1` | 诊断用「真跳过」子开关，**不改产物**（实测 20,992 B 不变）|

> **⟹ 如果你设了 `QCC_RT_DCE=1` 发现没变化，那不是你的错，是这个开关已经没用了。**

### C. 诊断输出类（不改产物，只打日志到 stderr）

| 变量 | 输出内容 |
|:--|:--|
| `QCC_DUMP=ir` | 等价 `--ir`（IR L1 导出）|
| `QCC_NODES=1` | `[NODE] 型=%d 子0=%d 子1=%d` 逐节点 |
| `QCC_VARS=1` | `[VARS] 变量数=%d` |
| `QCC_IR_NOREC=1` | S0-3 负例开关：关掉 IR 记录（用于验证「关掉后必须响亮失败」）|
| `QCC_ELF_DBG=1` | `[ELF] main起=%d 主虚=%d 布虚=%d 布长=%d` |
| `QCC_DCE_VERBOSE=1` | DCE 决策过程（含「内存不足 ⟹ 关闭裁剪」）|
| `QCC_OPT_VERBOSE=1` | 优化过程细节 |
| `QCC_DBG_TIME=1` | **四段计时**：`词法+宏展开 / 解析 / 码生成 / 对象写`（毫秒）|

### D. 内部判据 / 故障注入（**普通用户不要碰**，10 个）

| 变量 | 用途 |
|:--|:--|
| `QCC_FI_ALLOC=1` | 故障注入：分配失败路径（判据驱动）|
| `QCC_FI_NODE=1` | 故障注入：节点检查点（判据驱动）|
| `QCC_FI_SLOT=1` | 故障注入：槽位检查点（判据驱动）|
| `QCC_DCE_TEST_DROP=<fn>` | **故障注入**：强行把某函数标为不可达，验证「漏边必须响亮回退」 |
| `QCC_PREBASE=<n>` | 判据用：强制大预基，验证「零重跑」路径 |
| `QCC_TEXT_BASE=<hex>` | 覆盖 PE `BaseOfCode`（R898）|
| `QCC_DBG_INV_BREAK=1` | 不变式违例时断点 |
| `QCC_DBG_IRCAP_MAIN=1` / `QCC_DBG_IRCAP_CHAIN=1` | IR 容量守卫验证 |
| `QCC_DBG_L0REC=1` | L0 访存记录 |

## 四 · 组合示例（真实场景）

### 场景 1：新人第一次跑（只有 exe，没有仓库）

```powershell
$env:QCC_RT_PATH = 'C:\jiayan\qcc_rt.c'    # ← 必须，否则响亮失败
.\qcc_zh_seed.exe hello.c -o hello.exe
```
**注意**：只拷 exe 不够，**运行库 `qcc_rt.c` 是必需品**。缺了会 fail-closed 报错（这是设计，不是 bug）。

### 场景 2：给 AI 用（结构化输出）

```powershell
.\qcc_zh_seed.exe util.c -c -o util.obj --dj                 # 错误是 JSON
.\qcc_zh_seed.exe util.c -o util.exe -graph graph.json       # 代码图谱
.\qcc_zh_seed.exe util.c -o util.exe -graph g.json --interface --refs r.json
```

### 场景 3：验证「它没骗我」

```powershell
.\qcc_zh_seed.exe srclib_jiayan\qcc_zh.jy -o v1.exe          # 自举第一代
.\v1.exe srclib_jiayan\qcc_zh.jy -o v2.exe                   # 第二代
# v1 与 v2 的 SHA256 必须完全相同 —— 这是「自举收敛」的定义
```

### 场景 4：只看 IR、不要产物（研究用）

```powershell
.\qcc_zh_seed.exe x.c --ir-only > ir.txt    # 产物写向 NUL，只出 IR
```

### 场景 5：排查产物体积

```powershell
.\qcc_zh_seed.exe min.c -o a.exe              # 默认（已裁剪）≈ 21 KB
$env:QCC_NO_DCE='1'; .\qcc_zh_seed.exe min.c -o b.exe   # 全量 ≈ 385 KB
$env:QCC_NO_DCE='' ; $env:QCC_DCE_VERBOSE='1'; .\qcc_zh_seed.exe min.c -o c.exe
```
