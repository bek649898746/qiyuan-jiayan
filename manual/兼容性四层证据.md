# 甲言 · 兼容性 —— 突出点的证据链

**启元整理 · 2026-10-13 · 2026-10-15 复核更新** · 依据：本机实测 + 九线压测报告 + 291 项逐项表

## 一、四层兼容（由硬到软）

### 层 1 · **C ABI 兼容**（产物级 · 最硬）

| 证据 | 实测 |
|:--|:--|
| 甲言 `-c` 产出物是**标准 COFF** | `pe-x86-64` · `.text(0xf0,RELOC,CODE)/.rstr/.rdbl/.data` · 符号为**裸名** `T jy_add` / `U jy_add` |
| **g++ 能直接链接甲言的目标文件** | 甲言 `jy_export.obj` + `g++ use_jy.o` → **`jy_mixed.exe`（88,479 B）跑通**：`jy_add(20,22)=42` · `jy_val=42` · **exit 0** |
| 与 C 生态共生 | 可链 C 对象文件与静态库；**msvcrt 标准 C 库导入 120+ 函数**（printf/文件IO/内存/字符串/数学/时间） |
| **族 12「互操作 / ABI」逐项** | **15 / 15 全部已实现** 👇 |

**族 12 十五项（全部 ✅）**：C ABI 完整 · 链接模型完整 · 外部库绑定(C) · 符号可见性控制 · **C++ 互操作** · 异常 ABI ·
动态库加载(dlopen) · 调用约定控制 · 导出表控制 · FFI 安全标记(unsafe) · extern 块细化 · 内联汇编 asm ·
系统调用接口(syscall) · 目标架构特性检测 · 静态库归档/链接细化

> **这一层的意义**：甲言不是"自己玩的语言"—— **它的产物可以直接进入 C/C++ 世界**（链接、调用、被调用）。
> 这是**"能落地"的工程凭证**，也是**第三方最容易亲手验证**的一条。

### 层 2 · **语言写法兼容**（语法级）

**用甲言从零写出 9 种语言的实现，329 用例 / 326 通过**：

| 线 | 成果 | 甲言拦我 |
|:--|:--|--:|
| Java → **真 JVM 字节码** | **17 / 17** | 10 次 |
| Python（解释器）| **35 / 35** | 1 次 |
| Go（解释器）| **44 / 44** | 0 次 |
| Rust（解释器）| **55 / 55** | 0 次 |

**最硬的几处**：Rust 的**尾表达式即返回值**、`&self` 隐式接收者（间接寻址）· Go 的 `for` 三子句（**源码序≠执行序**）·
Python 的**缩进感知词法**（INDENT 值不固定，只能按种吃）· Java 的 **JVM 字节码逐条核对**（`a3`=`if_icmpgt`、`a7 ff f2`=−14 回跳）。

**拦截曲线 10 → 1 → 0**：Java 线 10 次（起手无名表，被 `R432/R464/R468/R476/C146/C155/A9005/A1007/A1001` 拦出来）
⟹ 补名表后 PY 1 次 ⟹ Go/Rust **0 次**（Rust 线约 **2,600 行甲言源码**零命名冲突）。

> **这一层的意义**：**别的语言的写法，搬进甲言基本能原样跑通。** 不是"翻译"，是**语法承载得住**。

## 二、为什么"兼容性"是最好的对外表达

| 相比 | 优点 |
|:--|:--|
| vs「**中文编程**」| 中文是**书写方式**，兼容性是**能力**。而且兼容性**不依赖读者对中文的好感**——技术评审只看能不能跑 |
| vs「**能编 git**」| 那属于**工程规模** —— 563 文件 → **540 通过 / 23 项确定性拒绝 / 零崩溃**（2026-10-15 独立复跑，331s）。**兼容性是已完成的事实**（族12 十五项 + g++ 链接 + 九线 329/326）|
| vs「**自举**」| 自举是**自我证明**（内向）；兼容是**对外开放**（能被别人用、能进别人的世界）|
| **可验证性** | 三条都能**第三方亲手复现**：拿甲言编个 obj → 用 g++ 链起来跑；拿 Rust/Go 写法写甲言程序；查 291 项表 |
