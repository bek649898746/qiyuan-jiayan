# 甲言 · 编译期检查清单（比 C 多出来的那层安全网）

> **一句话**：甲言是 **C 的超集 + 一层编译期安全网**。
> 同一段代码，`gcc` 放过去变成运行时崩溃，甲言在**编译期**就拦住，并告诉你**怎么改**。
>
> 本页每一条都是**实测**（2026-10-20 · Windows x64 · `qcc_zh_seed.exe` `39C6FC81`），
> 附测试代码 + 编译器原文 + 复算命令。**你可以自己贴进去试。**

---

## 一、总览：gcc 有的 / 甲言多出来的

| 检查 | `gcc -O2 -Wall` | 甲言 | 类别 |
|:--|:--|:--|:--|
| 使用未声明的标识符 | ✅ error | ✅ **A1001** | 共有 |
| 指针赋整数 | ✅ error | ✅ **A2001** + **给出修法** | 共有（甲言多给修法）|
| 括号不配对 | ✅ error（位置粗） | ✅ **指出第一个未闭合的开括号位置** | 共有（甲言定位更准）|
| **可空类型未解包就取值** | ❌ **C 里没有这个概念** | ✅ **A8001** | 🆕 甲言独有 |
| **变量未初始化就读取** | ⚠️ `-Wmaybe-uninitialized` 仅警告且常漏报 | ✅ **A4001 硬错误** | 🆕 升级为错误 |
| **`数据流` 声明缺初值** | ❌ 无此机制 | ✅ **A6089** | 🆕 甲言独有 |
| **数组常量下标越界** | ⚠️ `-Warray-bounds` 警告，UB | ✅ **A2001 编译期越界** | 🆕 升级为错误 |
| **函数名撞保留类型词** | ❌ 不存在（C 无中文关键字） | ✅ **A9001 + 解释你会看到什么误导性报错** | 🆕 甲言独有 |
| **关键字撞词（跳/短当变量名）** | ❌ 不存在 | ✅ **A9001 + 说明运行期后果** | 🆕 甲言独有 |

> **这不是"甲言比 gcc 好"** —— gcc 的定位是「C 有多快就多快，标准允许的你别拦我」。
> 甲言的定位是「**中文写程序的人，不该被内存崩溃打断**」。两者取舍不同。

## 二、逐条实测

### 1. 可空类型未解包就取值（A8001）—— C 里根本没有这个机制

**测试代码**
```c
函数 整 主(空) { 可空 整 甲 = 空; 返 甲 + 1; }
```

**编译器原文**
```
[ERR] A8001 可空类型: 变量 '甲' 未解包就取值 (值类型运算/传参/比较)
      — 先 解包 甲; 或 若(!判空 甲) { ... } 分支窄化
```

**为什么这是硬优势**：C 里 `int *p = NULL; *p` 是教科书级的崩溃源，编译器完全不管。
甲言把「可能为空」变成**类型的一部分**，用得着的地方不检查就不给过。
这是 Kotlin / Swift / TypeScript `strictNullChecks` 那一档的能力，**C 生态里没有**。

**而且给了两条修法**：`解包` 或 `判空窄化`。

---

### 2. 数组常量下标越界（A2001 编译期越界）

**测试代码**
```c
函数 整 主(空) { 整 a[3]; a[10] = 1; 返 0; }
```

**编译器原文**
```
[ERR] A2001 编译期越界: 数组 'a'[10] 越界 (大小 3)
```

**对比 gcc**：`a[10]` 在 C 里是**未定义行为**，`-Wall` 通常不报（要 `-Warray-bounds` 且优化级别合适才可能警告）。
甲言直接算出「大小 3，你访问 10」并拦住。

---

### 3. 变量未初始化就读取（A4001）—— 从警告升级为错误

**测试代码**
```c
构 盒 { 整 v; } 函数 整 主(空) { 盒 甲; 盒 乙 = 甲; 返 0; }
```

**编译器原文**
```
[ERR] A4001 明确初始化: 变量 '甲' 未初始化就读取 (声明须初始化或先赋值, 号合.0 #78; 词行 1541)
```

**对比 gcc**：`-Wmaybe-uninitialized` 是**警告**，而且对结构体整体拷贝这种场景**经常漏报**。
甲言是硬错误，且带**词法行号**（`词行 1541`）。

---

### 4. 数据流单赋值（A6089）—— C 里没有这个机制

**测试代码**
```c
函数 整 主(空) { 数据流 整 甲; 返 甲; }
```

**编译器原文**
```
[ERR] A6089 数据流: 声明 须 带 初值 —— `数据流 类型 名 = 初值;`
      (单赋值 语义 要求 值 在 声明 处 唯一 确定, 缺 初值 ⟹ 变量 永远 无法 取得 值)
```

**价值**：这是 **SSA（单赋值）语义**在语言层落地。名字一旦绑定就不再变，编译器能据此做更强的数据流分析。
C 里没有对应机制。

> ⚠️ 这条检查曾经有个 bug：缺初值时不是报错而是**编译器死循环挂起**（2026-10-18 发现并修复）。
> 现在能 5 秒内响亮报错 —— 这份文档的每个示例都是修完之后跑的。

---

### 5. 撞词诊断（A9001）—— 它知道你会看到什么误导性报错

**测试代码**
```c
函数 整 整(空) { 返 1; } 函数 整 主(空) { 返 0; }
```
（把函数命名为 `整`，撞了保留类型词）

**编译器原文**
```
[ERR] A9001 函数名 缺失 —— 名 大概率 撞了 保留 类型词 ('整'):
      返类型 消费后 直接 遇 `(` ⟹ 函数定义 被 静默丢弃
      (顶层解析 中断 ⟹ 误导性「未找到 主 入口」); 请 改名
```

**这条是全场最特别的一条**：它不只知道「错了」，还知道**如果不拦，你会看到什么**（`未找到 主 入口`），并解释为什么那个报错是误导性的。
—— 这叫「**诊断的元级别能力**」：编译器理解自己的解析路径会怎么失败。

再看关键字撞词那一条，把**运行期后果**也写出来了：

**测试代码**
```c
// 变量名用 跳（现在是跳转语句关键字）
若 (op == 0x99 && v == 0) 跳 = 1;
```

**编译器原文**
```
[ERR] A9001 关键字 '跳' 不能 作 赋值目标 —— `跳` 是 跳转 语句关键字,
      词法器 已 改写为 token ⟹ `跳 = 1;` 被 当 跳转语句,
      等号 与 右值 被 静默 丢弃, 且 生成 跳转到 不存在 的 标签
      (运行期 0xC0000005)
```

**现象 + 原因 + 机制 + 后果 + 崩溃码**，一句话说全。

### 6. 中文报错本身就是一个优势（这条容易被忽略）

上面所有报错**全中文、零英文术语**。

对比 gcc 同一个错误：
```text
error: initialization of 'char *' from 'int' makes pointer from integer without a cast [-Wint-conversion]
```
```text
[ERR] A2001 类型错配: 整数 42 赋给指针 'p' — 指针只能用地址或 空(0)
```

gcc 那句：**描述现象**（"makes pointer from integer"），**不说怎么办**。
甲言那句：**说明原因 + 直接给修法**（"只能用地址或 空(0)"）。

对一个**不会英文的初学者**，这个差别是「查词典半小时」和「立刻知道怎么改」。

## 三、代价：这层安全网不是白来的（诚实说）

| 代价 | 说明 |
|:--|:--|
| **不是 100% C 兼容了** | 有些**合法 C** 会被甲言拦住（如用 `跳` 作变量名、未初始化就用的写法）。甲言定位是「更安全的 C 超集」，不是「C 的逐字实现」|
| **编译器更复杂** | 35,264 行里相当一部分是这些检查。这也解释了为什么它会比预期慢 |
| **有已知漏网** | 实测发现：**常量除零**（`5 / 0`）目前**不报错**；部分借用场景也没拦住。这份清单不是"全覆盖" |

> 如实登记：本页 6 条是**实测能触发的**，不是"甲言所有检查的完整清单"。

## 四、怎么自己验

任何一条，三步复算：

```powershell
# 1. 把测试代码存成 t.c（注意 UTF-8）
# 2. 编
.\qcc_zh_seed.exe t.c -o t.exe
# 3. 看报错原文 —— 与本文对照
```

或用结构化诊断拿到 JSON（可被程序消费）：

```powershell
.\qcc_zh_seed.exe --dj t.c -o t.exe
# {"diagnostics":[{"code":"A8001","severity":"error","loc":{"line":1,"col":0},
#   "message":"...","fixes":["..."] ,"codeLine":"..."}]}
```

`--dj` 输出里带 **`code`（错误码，可检索）/ `fixes`（修复建议数组）/ `codeLine`（出错源码行）** ——
这是给 AI 和人同时准备的：人读 message，程序读 code。
