# 甲言 · 泛型单态化（`泛型函数` + `实例`）

> **一句话**：甲言有**两种泛型语法** —— 一个是真的单态化，一个是宏展开。
> **用错的那个有副作用陷阱，用对的那个才是真泛型。** 本页说清区别。
>
> 实测环境：2026-10-20 · `qcc_zh_seed.exe`（`39C6FC81`）· Windows x64

---

## 一、先看结论

| 语法 | 本质 | 副作用 | 状态 |
|:--|:--|:--|:--|
| **`泛型函数 名(T) = …` + `实例 名(整);`** | ✅ **真单态化**（源码级展开成独立符号） | **实参求值一次** | **推荐** |
| `泛型 名(参数)(表达式)` | ⚠️ **宏展开**（文本替换） | **实参可能求值多次** | 旧语法，有陷阱 |

**两句话记住**：
- 要真泛型 → 用 `泛型函数` + `实例`
- 见到 `泛型 名(参数)(表达式)` → 那是宏，别拿它做带副作用的实参

---

## 二、实测证据（你可以自己跑一遍）

### ① 基本用法

```c
泛型函数 恒等(T) = 函数 T 恒等(T x) { 返 x; }
实例 恒等(整);
实例 恒等(双);

函数 整 主(空) {
    整 甲 = 恒等[整](42);
    双 乙 = 恒等[双](3.5);
    输出("甲=%d 乙=%.1f\n", 甲, 乙);
    返 0;
}
```

```
甲=42 乙=3.5
```

### ② 副作用铁证：这是"真"与"假"的分界线

```c
泛型函数 平方(T) = 函数 T 平方(T x) { 返 x * x; }
实例 平方(整);

函数 整 主(空) {
    整 变 = 0;
    整 果 = 平方[整](变++);     // 注意：实参带副作用
    输出("变=%d 果=%d\n", 变, 果);
    返 0;
}
```

**实测输出：`变=1 果=0`**

- 若 `变=1` ⟹ 实参只求值一次 ⟹ **真单态化** ✅
- 若 `变=2` ⟹ 实参求值两次 ⟹ 宏展开 ❌

### ③ 符号级证据：编译成对象后看符号表

```powershell
.\qcc_zh_seed.exe -c mono.jy -o mono.obj
objdump -t mono.obj | findstr 恒等
```

能看到 **`恒等_整`** 和 **`恒等_双`** 两个**独立的真实符号**（不同地址）——
这是"单态化"的字面含义：每个类型参数组合生成一份独立代码。

---

## 三、`实例` 是必须的（不是可选优化）

**没有 `实例` 的类型组合，直接编译失败，不会静默回落成宏。**

```c
实例 恒等(整);       // 只实例化了 整
整 x = 恒等[整](1);   // ✅
长 y = 恒等[长](2);   // ❌ A1001 未声明/未实例化
```

这个设计是刻意的：**让"忘了实例化"变成编译错误，而不是偷偷退回宏展开**。

---

## 四、旧宏语法的陷阱（继续存在，但要知道）

```c
泛型 平方(甲) ((甲)*(甲))     // ← 这是宏！文本替换！
```

它的行为等价于 C 的 `#define`：

| 你的调用 | 宏展开后 | 结果 |
|:--|:--|:--|
| `平方(变++)` | `((变++)*(变++))` | **`变` 被加了 2 次** |

**这就是为什么它不能算真泛型**：
1. 实参重复求值（副作用被放大）
2. 没有类型检查（纯文本替换）
3. 报错定位会指到展开后的位置，不是你的源码

**结论**：旧语法适合"纯文本替换"场景（如常量表达式），**不要传带副作用的实参**。

---

## 五、为什么这件事重要

真单态化是**泛型能做大的前提**：

| 能力 | 宏展开 | 真单态化 |
|:--|:--|:--|
| 类型安全 | ❌ 无检查 | ✅ 每个实例独立检查 |
| 副作用 | ❌ 可能重复求值 | ✅ 只求值一次 |
| 调试 | ❌ 报错指到展开处 | ✅ 报错指到实例 |
| 代码体积 | 小（文本） | 大（每类型一份）—— 这是单态化的固有代价 |
| 能做递归泛型/泛型容器 | ❌ 困难 | ✅ 可行 |

代价也要说清：**单态化会让代码膨胀**（每个类型组合一份代码）。这是 C++ 模板/Rust 泛型共同的代价，不是甲言独有的问题。
