# 甲言 · 多语言实现（九条语言线）

> **一句话**：用**甲言**（中文关键字语言）写了**九种语言**的解释器 / 编译器前端 —— **85 个文件 / 69,497 行**，全部在仓库里，可逐条编译运行。

**为什么这是硬指标**：一门语言能不能干活，不看能否编译 hello world，而看**能不能实现别的语言**。
而"能不能实现"这件事，唯一有说服力的证明是 —— **源码摆出来，让别人自己编译跑一遍**。

## 一、立即可验（两条命令）

| 想验什么 | 命令 | 本机实测 |
|:--|:--|:--|
| **九条线的入口文件全部能编能跑** | `powershell -File scripts/verify_multilang.ps1` | **9/9 通过 / 31.6 秒** |
| **85 个文件逐个压测** | 见第四节（结果表 + CSV 明细） | **正例 70/80 = 87.5%**，负例 3/3 如期报错 |

零依赖：不需要 gcc、不需要 Python、不需要 JDK/Go/Rust/TS/C++/C# 任何官方工具链，也不需要联网。
只要仓库自带的 `qcc_zh_seed.exe`。

```powershell
.\qcc_zh_seed.exe examples\multilang\python\py1.c -o py1.exe
.\py1.exe
# PY-P1 缩进感知 词法分析器 (甲言 实现)
# ────────────────────────────────────────
# 名(x) 符(61) 数字(1) 换行
# ▶缩进(4) 名(print) 符(40) 名(x) 符(41) 换行
```

> ⚠️ **文件扩展名是 `.c`，内容是甲言**。甲言兼容 C，编译器按 `.c` 处理；源码里是 `静`/`整`/`字`/`空`/`循环`/`若`/`否`/`返`/`#包含`。
> 这一点曾让我在 2026-10-17 和 10-20 两次打捞失败——当时只按 `*.jy` 搜。**查"某种语言的源码"不能用扩展名当判据。**

## 二、九条线总览

| # | 线 | 目录 | 文件 | 行数 | 层级 | 每层压的招牌机制 |
|--:|:--|:--|--:|--:|:--|:--|
| 1 | **JS** | `js/` | 13 | 7,948 | **L1–L11** | 表达式求值 → 语句 → 函数 → 对象/数组 → 闭包 → 原型链（`jsl1` 85 行 → `jsl8/9` 1,228 行） |
| 2 | **JVM** | `jvm/` | 2 | 455 | J1–J2 | **栈式字节码解释器** + 真 `.class` 解析 |
| 3 | **Java** | `java/` | 25 | 3,824 | A1–A3 + 18 探针 | Java 源码 → **真实 JVM 字节码**（不是解释器）；A2 控制流跳转回填 |
| 4 | **C++** | `cpp/` | 12 | 14,122 | **C1–C12** | `cout <<` 链式流插入 + `<<` 双重身份（移位/流）、函数重载决议、类与继承（`cpp1` 488 行 → `cpp12` 1,608 行） |
| 5 | **C#** | `csharp/` | 11 | 32,692 | CS1–CS5 + 4 探针 | C# 基础层 → 类/属性/委托；`cs5.c` 单文件 **21,233 行**（全库最大） |
| 6 | **Go** | `go/` | 4 | 2,562 | G1–G4 | `x := v` 短变量声明 vs `var x int = v`（类型后置）、Go 的 `:=` 声明 / `=` 赋值语义分界、struct 与字段 |
| 7 | **Python** | `python/` | 4 | 1,801 | P1–P4 | **缩进感知词法**（发 INDENT/DEDENT）+ 栈式 VM + `if/elif/else·while·for range` + `def` |
| 8 | **Rust** | `rust/` | 6 | 3,010 | R1–R4 | `let` 默认不可变 / `let mut` 可变、类型标注后置、`println!` 宏、**`if` 是表达式**、尾表达式即返回值、`impl` 方法 + `&self` |
| 9 | **TypeScript** | `typescript/` | 8 | 3,083 | T1–T4 + 4 对照 | **编译期静态类型检查**：标注 / 推断 / 调用处实参检查 / `interface` 结构化类型（`Point{x,y,z}` 兼容、字段顺序无关） |
| | **合计** | | **85** | **69,497** | | |

### 设计手法：每线都是 L1 → Ln 逐层加码

不是"一口气写完一个大解释器"，而是**每一层都是一个独立可跑的完整程序**：

```
L1  最小可跑（词法 + 表达式）        ← 85–493 行
L2  加控制流（if / while / for）
L3  加函数（参数 / 返回 / 递归）
L4  加数据结构（struct / 对象 / 接口）
Ln  加该语言最独特的机制
```

**这个形态本身就是证据**：`jsl1.c` 85 行就能跑，`jsl9.c` 1,229 行也独立能跑 —— 说明不是靠框架堆出来的，是一层一层真加进去的。
每层压的是那门语言**最有辨识度**的东西（Go 的 `:=`、Rust 的不可变绑定、Python 的缩进、C++ 的 `<<` 双身份），而不是把 C 语法换个壳。

## 三、⚠️ 验收口径与局限（这一节比数字更重要）

| # | 局限 | 说明 |
|--:|:--|:--|
| 1 | **无官方编译器交叉对照** | 本机**没有 JDK / Go / Rust / TypeScript / C++ / C# 任何一条工具链**。正确性依靠**逐字节手验字节码 + 自建 VM 执行**，**不是**由官方编译器判定的 |
| 2 | **「全绿」的确切含义** | = **在本套判据下全绿**，**不等于**「与官方行为一致」 |
| 3 | **这些是原型，不是完整实现** | 每线压一个招牌机制，**不是**「九个语言的完整支持」 |
| 4 | **C# 与 C++ 内核不同源** | C# 线把对象变量由**值语义**改为**引用绑定**，而 C++ 线已投递未回改 ⟹ **此差异属未结项**，如实记录 |
| 5 | **旧计数不可复算** | 历史记录「329 用例 / 326 通过」来自内部审计档案（逐例预期 + 验收记录），**本仓库只提供源码本体，不重复该计数**。对外可复算的是本文第二节与第四节的数字 |

> 口径原则：能核验的说清怎么核验，不能核验的说清边界 —— 见 [`数据口径与核验方法.md`](数据口径与核验方法.md)。

### 剩下 10 个为什么不过 —— 全部有明确根因

| 根因 | 数量 | 文件 | 说明 |
|:--|--:|:--|:--|
| **甲言关键字表演进**：`跳` 现为跳转语句保留字 | **7** | `java/kw1.c` `min2/3/5/6/11/15.c` | 这些文件把 `跳` 当变量名用；现在词法器当关键字处理 ⟹ `A9001` |
| **甲言关键字表演进**：`短` 现为类型词 | 1 | `csharp/cs9.c` | 形参名 `短` 与类型词冲突 ⟹ `A9001` |
| 源文件自身括号错 | 1 | `java/min4.c` | `多余右括号 '}' 行 158` —— **文件本身的 bug** |
| `串长` 内建限制 | 1 | `js/jsl7.c` | `串长` 只适用原生串（带 4 字节长度前缀），对普通 `字` 缓冲不适用 |

#### 为什么会撞词 —— 这不是随意加限制，是一次刻意修复

| 项 | 内容 |
|:--|:--|
| **机制** | `qcc_zh.jy` **L7766** `若 (!比较字符串(串值, "跳")) 返 大于;` ⟹ `跳` 被词法器改写为**跳转语句关键字 token**；**L7771** 同理把 `短` 改写为**类型词 token** |
| **引入** | 提交 **`f6ce808a`** · **2026-10-05** · 第455站第八十八轮 · 「语句关键字 **撞词硬收**（跳/断/续/循环/若/否/返/遍/择/例/缺/做 ⟹ A9001）」 |
| **动机** | 撞词会导致**静默崩溃**：`跳 = 1;` 被当成跳转语句 ⟹ `=` 与右值**被静默丢弃** ⟹ 生成跳转到不存在的标签 ⟹ **运行期 `0xC0000005`** |

编译器自己的报错把因果写得最清楚：

```text
[ERR] A9001 关键字 '跳' 不能 作 赋值目标 —— `跳` 是 **跳转 语句关键字**,
词法器 已 改写为 token ⟹ `跳 = 1;` 被 当 跳转语句, 等号 与 右值 **被 静默 丢弃**,
且 生成 跳转 到 不存在 的 标签 (运行期 0xC0000005)
```

**⟹ 那次改动是把「运行期静默崩溃」换成「编译期响亮报错」。**
所以这 7 个 java 文件在 10-05 之前，**就算能编过，跑起来也是崩的** —— 硬收之后它们从「能编但会崩」变成「编不过」，**这是升级，不是退步**。

> **这 8 个关键字冲突原样保留，不修。** 它们是一份旧代码遇上语言演进的活证据。
> 想自己验可以改个名（`跳` → `跳位`）再编，会立刻通过 —— 但改了就没证据了。

> ⚠️ **另一个坑**：`rust/否链2.c` **编译 rc=0，但运行是死循环**。
> 它是首次压测把脚本卡死 10 分钟的元凶 —— 因为脚本编译成功后会直接运行产物，**没给运行环节超时**。
> 这就是「孤儿进程」类事故。**任何跑陌生程序的脚本，运行环节必须 `WaitForExit(N)` + `Kill`。**

**完整明细**：[`examples/multilang/_stress_result_20261020.csv`](../examples/multilang/_stress_result_20261020.csv)（85 行：线 / 文件 / 类别 / rc / 耗时 / 产物字节 / 运行首行 / 备注，任何人可复算）

## 五、跨语言价值（这才是做这件事的真正意义）

九条线摊开后，**同一维度上各语言的分歧**反而成了甲言的测试用例：

| 维度 | 九线的分歧 | 甲言的处理 |
|:--|:--|:--|
| **语句分隔 / 块结构** | Python：换行 + **缩进**；Rust：**分号**、换行完全无意义（两者正相反） | INDENT / DEDENT **直接当块括号**用；Rust 侧按分号成句 |
| **调用回填** | 九线共识：函数体先编、调用地址后填 | **两阶段回填**（先编完所有函数体，再统一回填）—— 此坑只犯过一次 |
| **作用域槽命名** | C++ / C# 暴露最狠（全局槽按名复用） | 隐藏槽用 `#` 前缀（`#` **不是合法标识符首字符** ⟹ 用户代码永远撞不上，无需转义） |
| **类型检查时机** | Rust / TypeScript 在**编译期**；其余在运行时 | 甲言**两者都能承载**（TS 线每例打印「变量 → 类型」表，故"通过"不是碰巧） |
| **类型系统范式** | Java/Rust 名义类型（靠名字） vs **TS 结构化类型**（靠形状） | 均已实现（`Point{x,y,z}` 兼容、字段顺序无关、`Point` 与 `Line` 不兼容） |
| **对象模型** | C++ **值语义** vs C# **引用绑定** | **九线里唯一互相冲突的维度**（未结项，已如实记录） |
| **声明形式** | Go：`x := v` 与 `var x int = v` 并存，且 `:=` 是声明、`=` 是赋值 | 两条语义分界都实现（G1 压的就是这个） |
| **可变性默认值** | Rust：`let` 默认**不可变**，改它要 `let mut`；其余语言默认可变 | 已在 R1 实现编译期拒绝 |

**结论**：甲言不只"能用中文写程序"，它**能承载九种语言的语义分歧** —— 这比任何单个 demo 都更能说明它的表达力边界。
