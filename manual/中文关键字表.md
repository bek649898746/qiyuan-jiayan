## 一、一句话结论

**中文覆盖「语法骨架」，运算符沿用 C。中文关键字共 42 个。**

| 类别 | 词元类型数 | 中文形态 |
|:--|--:|:--|
| **有中文关键字**（语句 / 类型 / 修饰） | **18** | ✅ 有 —— 中文原生 + 英文 C 兼容别名 |
| **纯符号**（运算符 / 标点 / 字面量） | **54** | ❌ 无 —— 与 C **完全一致** |
| 合计 | 72 | — |

运算符与标点（`+ - * / % = < > & | ^ ~ ! ? : ; , . -> [ ] { } ( )` 及复合赋值）
**没有也不需要中文形态**，与 C 一致。

⟹ 甲言 = **关键字中文化 + 符号层保持 C**，这正是它能兼容 C 的边界。
所以可以**中英混写**：`整`/`int`、`若`/`if` 是同一件事。

### ⚠️ 只有一个「只能用英文写」

| 词 | 中文名 | 说明 |
|:--|:--|:--|
| `_Alignof` | ❌ **无** | C11 对齐查询，词法器只认英文拼写（返词元类型 `容吉一`） |
| `_Atomic` | ❌ **无** | C11 类型修饰符（单线程下当普通类型，无原子语义） |

> 其余 C11 关键字均有中文名：`_Noreturn`→`不返回` · `_Generic`→`类属`。

## 四、⚠️ 血泪坑：中文关键字**不能**用作变量名

源码 `语句关键字表[]` 的注释里记着实测事故（2026-10-05）：

```c
整 跳 = 0;              /* ← 跳 是关键字！ */
循环 (跳 < 5) { 跳++; }
```

**后果**：编译 **`rc=0` 零报错**，运行期直接 **`0xC0000005` 崩溃**。
因为 `跳` 被词法器当成 `>` 运算符，整条声明被**静默丢弃**。

同类：`整 while = 5;` → 编译通过，**读出来是 0**（静默错值）。

> **规则**：上表所有词**一律不能作变量名 / 函数名**。命名拿不准时先查本表。
> 这类错误**编译期不报**，只在运行期发作 —— 宁可查表，别赌。

## 五、完整可跑示例

新建 `示例.jy`：

```c
/* 甲言示例：中文关键字 + 中文标识符 */
整 计算阶乘(整 甲) {
    若 (甲 <= 1) {
        返 1;
    }
    返 甲 * 计算阶乘(甲 - 1);
}

整 main() {
    整 和 = 0;
    遍 (整 序号 = 1; 序号 <= 5; 序号++) {
        和 = 和 + 计算阶乘(序号);
    }
    输出("阶乘之和 = %d\n", 和);

    若 (和 > 100) {
        输出("超过 100\n");
    } 否则 {
        输出("未超过 100\n");
    }
    返 0;
}
```

编译运行：

```powershell
gcc -O2 -Wall -Werror srclib/qcc_x86.c -o qcc_x86.exe
.\qcc_x86.exe 示例.jy -o 示例.exe
.\示例.exe
```

预期输出（**2026-10-15 实测，与预期逐字一致**）：

```text
阶乘之和 = 153
超过 100
```

> **实测备注**：源文件用**中文名**时，编译器**回显的文件名会乱码**（如 `ʾ��.exe`）。
> 那是控制台代码页问题，**exe 正常生成、运行输出正确**。介意可改用英文文件名。
