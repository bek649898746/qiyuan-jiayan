# 甲言 · 快速上手

**目标：从零到跑通，并知道「怎么算跑对了」。**

本页只讲**怎么用**；原理、架构、创新点见 [README](../README.md)。
本页所有命令都可在 Windows 上直接复制执行。

---

## 一、这是什么

甲言（jiayan）是一门**中文编程语言**，也是一套完整的**中文编译器工具链**：

- **关键字可以是中文**：`整` `若` `否` `遍` `返` `循环` `择` …（共 **38 个**中文关键字 = 15 语句 + 23 类型修饰，见 [中文关键字表](中文关键字表.md)；`输出` 是内建函数，不是关键字）
- **兼容 C**：同一套工具链也能编译 C 代码，中英文可混写
- **自举**：编译器能编译自己，多代产物 SHA256 逐字节相同（收敛）
- **直出 PE**：直接产出 Windows x86-64 可执行文件，不依赖外部链接器

> 一句话：**你用中文写代码，它给你能直接运行的程序。**

## 二、前置要求（分两档：跑程序 = 零依赖 · 重建源码 = 才要 gcc/Python）

| 组件 | 用途 | 必需性 |
|:--|:--|:--|
| **Windows x64** | 目标平台（当前仅支持） | ✅ 必需 |
| **PowerShell 5.1+** | 执行构建脚本 | ✅ 必需（系统自带） |
| **（无额外依赖）** | **只想编译 / 运行甲言程序** | ✅ **零依赖** —— 用仓库自带 `qcc_zh_seed.exe`，**不需要 gcc，也不需要 Python** |
| **MinGW-w64（gcc）** | **仅**「重建 C 版历史信任根」时需要（英文链 `build.ps1` 已从对外路径撤出） | ⬜ 可选（用不到就别装） |
| **Python 3.x** | **仅**跑测试套件 / 行为断言 / 验证脚本时需要 | ⬜ 可选（想跑测试才装） |
| QEMU + LoongArch gcc | 仅 `tests/loong` 交叉编译回归 | ⬜ 可选 |

### ⚠️ 关于「零依赖」（实测口径）

「甲言自身零依赖」是**字面意思**，以下是 2026-10-15 本机实测：

- **甲言编出来的程序**：运行时不需要任何外部工具链
- **甲言编甲言（自举）**：不需要外部编译器 —— **把 `gcc` / `g++` 从 `PATH` 里完全移除后，仍能编出可运行 exe**
- **仓库自带种子编译器** `qcc_zh_seed.exe` ⟹ clone 后**直接可用**，不必先构建任何东西

> ⟹ **只编译 / 运行单个程序 → 零依赖（gcc 与 Python 都不需要）。**
> **要重建 C 版历史信任根 → 才需要 gcc；跑测试套件 → 才需要 Python 3.x。中文主链的自举验证两者都不需要。**

自检：

```powershell
# 0) 只想编译运行甲言程序（零依赖）—— 不必自检，直接编一个试试（下面这条已实测可跑）：
.\qcc_zh_seed.exe examples\成绩.jy -o 成绩.exe ; .\成绩.exe

# 只有在「从源码重建编译器 / 跑完整验证」这条路上，才需要确认这些工具齐备：
gcc --version
python --version
```

## 三、三步跑通

### 第 1 步 · 克隆

```powershell
git clone https://gitee.com/zheng-yuhe-from-guangdong/qi-yuan--jia-yan.git
cd qi-yuan--jia-yan
```

### 第 2 步 · 拿到编译器

仓库**已自带**一个不动点编译器 `qcc_zh_seed.exe`（15,245,824 字节 ≈ 14.54 MiB，SHA 前缀 `39C6FC81` = 当前不动点本身）——**clone 下来就能用，不需要先装 gcc，也不需要用 gcc 编任何东西**：

```powershell
.\qcc_zh_seed.exe --help          # 列出 27 项开关，确认可用
```

想从源码自己重建编译器、或跑完整自举验证 —— 见下文**第四节**（验证自举）与**第六节**（从源码重建）。

> ⚠️ **不要**用 `gcc` 编译 `srclib/qcc_x86.c` 来充当编译器：那份 C 原版停更于 2026-09-06、只有 22,600 行，编译 34,335 行的中文主源会**死循环**（`scripts/build_zh.ps1` 的 S2b-2 记录在案）。它只作为可审计的**历史信任根**保留。

### 第 3 步 · 编译并运行第一个程序

新建文件 `hello.jy`：

```c
整 主() {
    输出("你好，甲言！\n");
    返 0;
}
```

```powershell
.\qcc_zh_seed.exe hello.jy -o hello.exe
.\hello.exe
```

终端输出 `你好，甲言！` ⟹ **成功**。

> **也支持全英文写法**：把 `整`→`int`、`输出`→`printf`、`返`→`return` 即可，效果一致。

## 四、⭐ 怎么验证「自举」（本项目最核心的一条）

「自举」= 编译器编译自己，多代产物哈希完全相同。这是**确定性**的硬证据。

```powershell
powershell -ExecutionPolicy Bypass -File scripts/build_zh.ps1
```

脚本流程：编译宿主 → 宿主编译甲言源码得 `v1` → `v1` 编自己得 `v2` → `v3` → `v4` → `v5` → 比对哈希。

### ✅ 判据：看 `v2 == v3 == v4 == v5`

脚本打印：

```text
[OK] 自举收敛达成: v2==v3==v4==v5 = XXXXXXXX
```

**四个哈希完全相同 ⟹ 自举收敛成立**，这就是「跑对了」。

### ⚠️ 关于脚本里的 `$expected`（务必读）

脚本内记了一个 `$expected` 哈希（俗称「不动点」）。判据是：

```
v2 == v3 == v4 == v5   且   v2 的前 8 位 == $expected
```

- **源码每次合法修改，`$expected` 都会变** —— 这不是故障。
- 若你**原封不动** clone 下来却对不上 `$expected`：
  说明仓库记录的 `$expected` **滞后于源码**（作者改了源码未同步更新脚本），
  **此时 `v2..v5` 若仍全等，自举本身是成功的**，只是「仓库记录值」没跟上。
- 报告问题时**请附上完整输出**（五个哈希 + expected），方便定位。

## 五、三个构建脚本怎么选

仓库里有三个 `build*` 脚本，用途不同：

| 脚本 | 链条 | 用途 | 说明 |
|:--|:--|:--|:--|
| **`scripts/build_zh.ps1`** | **中文链** | ⭐ **主入口**：甲言中文源码自举验证 | 当前主力，`expected` 随最新提交更新 |
| ~~`scripts/build.ps1`~~ | ~~英文链~~ | ⚠️ **已从对外路径撤出**：它编译的是废弃镜像 `qcc_work.jy`（中文字符仅 5.8%），且在非仓库根目录会静默产出崩溃产物。详见 README「已知问题」第 1 条 | — |
| `scripts/build_rt.ps1` | 运行时 | 单独构建运行库 `qcc_rt.c` | 小工具 |

> **新手建议**：直接跑 `scripts/build_zh.ps1`（中文链、当前主力）。
> ⚠️ **英文链 `build.ps1` 不要用**：已知会在非仓库根目录静默产出缺运行库的残缺编译器（rc 仍 0，一运行 `0xC0000005`）。

## 八、常见坑（都是实测踩过的）

| # | 现象 | 真正原因 | 正解 |
|:--|:--|:--|:--|
| 1 | 编译「成功」但程序行为异常 / 崩溃（如 `0xC0000094` 除零） | 环境变量 `QCC_RT_PATH` 指向了**目录** | 必须指向**文件** `qcc_rt.c` 本身；或不设它、并让 cwd 在仓库根 |
| 2 | 多行宏 `#define M \` 结果恒为 0，且**无任何告警** | 源文件以 **CRLF** 存盘（反斜杠续行被破坏） | 演示/测试源码统一用 **LF** |
| 3 | `-o` 给了绝对路径，产物却落在 `a.exe` | 路径处理限制 | 用**相对路径**，或在源码所在目录内执行 |
| 4 | 报「无法打开」源文件 | 传了绝对路径 / cwd 不对 | 用**相对路径**，并确认 cwd 在仓库根 |
| 5 | 一键构建第 4 步报 `python : 无法将...识别为 cmdlet` | **未装 Python** | 装 Python 3.x（见第二节） |
| 6 | 中文源码编译报编码错 | 源文件编码 | 用 **UTF-8** 或 **GBK** 保存均可，勿用 UTF-16 |
| 7 | 源文件用**中文名**（如 `示例.jy`），编译回显 `ʾ��.exe` 乱码 | 控制台代码页与文件名编码不一致 | **功能正常** —— 实测 exe 正常生成且运行输出正确；仅回显乱码。介意可改用英文文件名 |

## 九、目录导航（哪些要管，哪些别管）

```
srclib/              编译器与工具链（C 版）
  qcc_x86.c          甲言编译器（C 原版 · 历史信任根 · 普通用户无需使用）
  qcc_rt.c           运行库
  asm_zh.c           中文汇编器
  jyld.c             COFF 链接器
  jycc.c             编译驱动
srclib_jiayan/       甲言中文源码（自举主体）
  qcc_zh.jy          中文主源
seed/                种子（自举起点）
tests/               测试（qcc / behavior / kernel / unit / loong）
examples/            示例程序
scripts/             构建与测试脚本（⭐ 使用者一般只需 build_zh.ps1；build_rt.ps1 是小工具；
                     其余是内部检查器与生成器，供开发/审计用，可忽略）
manual/              📖 本页所在（面向使用者的公开文档）
```

> **其余目录**（`scratch_*`、`probes/`、`memory/`、`docs/` 等）为**项目内部工作目录**，
> 使用者无需关心；它们可能不随仓库分发。
