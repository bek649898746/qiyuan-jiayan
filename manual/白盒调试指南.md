## 〇 · 这是什么

甲言把内部状态导出了 **27 个环境变量开关**。它们是「白盒」的实际入口：
**不修改源码，就能看见编译器内部发生了什么。**

**为什么 AI 需要它：** AI 不会翻源码找开关。它只读 `--help` 和文档。
所以这份文档的作用是——**把这 27 个开关从「存在」变成「可发现」。**

## 一 · 按症状查（最常用的一页）

| 你的症状 | 开这个 | 会看到 |
|:--|:--|:--|
| **「编译为什么这么慢」** | `QCC_DBG_TIME=1` | 四阶段计时：词法/解析/码生成/对象写 |
| **「变量到底在哪个栈槽」** | `QCC_VARS=1` | 变量表全量：名字/偏移/指深/元素尺寸 |
| **「这段代码生成了什么」** | `QCC_DUMP=ir` | IR 侧表：控式/段双/类型/值/所有权状态 |
| **「编译器看到了哪些词元」** | `QCC_DUMP=tokens` | 词元流全量（含行列号） |
| **「AST 长什么样」** | `QCC_DUMP=ast` | 节点树（根/节点数/顶层函数数） |
| **「类型是怎么推断的」** | `QCC_DUMP=types` | 类型表：尺寸/对齐/字段 |
| **「函数表里有什么」** | `QCC_DUMP=funcs` | 函数表：标号/返回构序/错误码 |
| **「这个符号为什么找不到」** | `QCC_DBG_FWD=1` | 前向声明尝试记录 |
| **「重载选了哪个」** | `QCC_DBG_OV=1` | 重载解析决策（含参个数/是否有同名） |
| **「报错说缺分号，我看不出来」** | `QCC_DBG_SEMI=1` | 分号判定现场：词位 + 前后词元 |
| **「调试信息行号对不上」** | `QCC_DBG_FMAP=1` | 函数起止行号映射 |
| **「命名空间解析错乱」** | `QCC_DBG_NS=1` | 命名空间注册/查找全过程 |
| **「宏展开结果不对」** | `QCC_DBG_INL=1` | 函数宏展开体 |
| **「有没有被静默兜底吞掉」** | `QCC_DBG_SILENT=1` | 静默兜底触发点（零静默纪律的量化工具）|
| **「参数槽算错了吗」** | `QCC_DBG_ARG=1` | 参数槽/栈高计算 |
| **「全局表有没有膨胀」** | `QCC_DBG_REENT=1` | 表竞技场：张数/复用次数 |
| **「节点属性怎么读」** | `QCC_NODES=1` | 单节点：型/子0/子1 |

## 三 · 实测样例（真实输出，可直接对照）

### 3.1 `QCC_DBG_TIME=1` —— 判断「慢在哪一段」

```powershell
$env:QCC_DBG_TIME='1'
qcc_x86 src.jy
```

**实测输出（小源）：**
```
[TIME] 词法+宏展开=19ms 解析=27ms 码生成=87ms 对象写=21ms
[TIME] 合计=154ms 总=374ms 占比=41% 词元=12152
```

**怎么读：**
- 四个数是**四阶段**累计（毫秒）
- `占比=41%` 表示四阶段占墙钟的 41%，剩下是进程启动/链接等固定开销
- **典型：大源上「码生成」占 77%** ⟹ 优化优先看那一段

### 3.2 `QCC_VARS=1` —— 查变量的栈布局

**实测输出（首两行）：**
```
[VARS] 变量数=513
[VARS] <变量名> off=<栈偏移> 指深=<n> 指元素=<n> 指内=<n> 长=<n> ...
```

**怎么读：**
- `off` 是相对帧指针的偏移，**负数表示局部变量**
- `指深` / `指元素` 决定解引用的步长
- **典型用途：怀疑「变量被算成错误宽度」时，直接看这里**

### 3.3 `QCC_DUMP=ir` —— 看生成的 IR

**实测输出（21,818 行，节选）：**
```
-- IR 类型级侧表 (容量 目低=4096, 类型数=3) — 左戊一=范围下界 半退三=范围上界 度散=父类型序; -1=无界/无, 0=未落位 --
-- IR 值级属性位 (实薄.现高 高 8 位; 256=溢出位8, 512=空指针位9) --
-- IR 节点级侧表 (控式: 1=循环 2=条件 3=分支...) --
    节[8] 控式=2 段双=0 型=8 值=0
    节[124] 控式=1 段双=0 型=9 值=0
-- IR 值级侧表 读端 (总子=所有权状态机: 0=普通 1=移动后 2=不可变借用 3=可变借用) --
```

**怎么读：**
- `控式`：1=循环 2=条件 3=分支
- `型`：节点类型码
- `总子`：**所有权状态机**（这是甲言借用检查的内核数据）

### 3.4 `QCC_DBG_SEMI=1` —— 排查「缺分号」误报

**实测（故意写错 `整 a = 1 返 a;`）：**
```
[SEMI2] 词位=12126 容量=2097152
  [12117] '整' 型=2 行=1601
  ...
```

**怎么读：**
- `词位` 是判定失败的位置
- 下面列出前后词元 —— **一眼看出编译器把哪个词当成了分号缺失点**

### 3.5 `QCC_DBG_FWD=1` —— 查「符号找不到」

**实测（218 行，节选）：**
```
[FWD-TRY] _bump_top 行=98 词位=49 目系=1 次型=17
```

**怎么读：** 每次「向前找声明」的尝试都打一行 ⟹ 找不到的那个名字会反复出现。
**典型用途：A1001 未声明错误，看它到底找了哪些位置。**

## 四 · 组合用法（按场景）

### 场景 A：怀疑「某变量宽度算错」

```powershell
$env:QCC_VARS='1'; $env:QCC_DUMP='types'
qcc_x86 src.jy
```
变量表给你「实际算出的偏移」，类型表给你「应该的尺寸」——**两边对照即可定位。**

### 场景 B：怀疑「编译慢在某个阶段」

```powershell
$env:QCC_DBG_TIME='1'
qcc_x86 src.jy
```
**先定位到阶段，再决定要不要深挖。**

### 场景 C：怀疑「借用检查误报」

```powershell
$env:QCC_DUMP='ir'
qcc_x86 src.jy
```
看 `-- IR 值级侧表 读端 (总子=所有权状态机) --` 那一段。

### 场景 D：怀疑「有错误被静默吞掉」

```powershell
$env:QCC_DBG_SILENT='1'
qcc_x86 src.jy
```
**零静默是甲言的纪律，这个开关就是用来验证纪律有没有被违反的。**

## 五 · 常见误用

| 误用 | 正确理解 |
|:--|:--|
| 「开了 `QCC_DBG_TOK` 但没输出 ⟹ 开关坏了」 | **是那条路径没走到。看是否只有 `OK:` 一行** |
| 「`QCC_DUMP=ir` 输出 2 万行没法看」 | **配 `\| Select-String '关键词'` 过滤，别直接读** |
| 「`QCC_DBG_TIME` 的合计 < 墙钟」 | **正常**。差额是进程启动/链接等固定开销 |
| 「故障注入开关（`QCC_FI_*`）能不能日常开」 | **不能**。它们是故意弄坏的测试工具 |
| 「`QCC_SMALL_HEAP` 开了会更快吗」 | **该开关已移除（R896）**。它原来是「构建期」读的，会把被构建的编译器永久限制在 256 MiB，现已恒定 768 MiB |
