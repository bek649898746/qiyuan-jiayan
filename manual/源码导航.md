## 四、别用眼睛读，用这三个接口

三个接口都**零依赖**（不需要 gcc / Python），`qcc_zh_seed.exe` 自带：

| 接口 | 命令 | 拿到什么 | 耗时（34k 行实测） |
|---|---|---|---|
| **接口表面** | `qcc_zh_seed.exe --interface srclib_jiayan/qcc_zh.jy` | 1,009 函数的签名 + 85 结构体布局（字段偏移/大小）+ 46 typedef + 126 枚举，JSON | **约 104 秒** |
| **代码知识图谱** | `qcc_zh_seed.exe -graph g.json <src>` | 函数/结构体实体 + 调用关系 + 布局风险分级，JSON | ⚠️ **约 11 分钟**（需完整编译） |
| **引用查询** | `qcc_zh_seed.exe --refs <src>` | 「谁引用了 X」：按名去重的 (名, 行号) 表，JSON | 约 104 秒（同解析期） |

```powershell
# 想快速搞清结构 —— 用 --interface（100 秒级）
.\qcc_zh_seed.exe --interface srclib_jiayan\qcc_zh.jy > iface.json

# 想看调用关系 —— 用 -graph（分钟级，仅在小源上做）
.\qcc_zh_seed.exe -graph g.json examples\成绩.jy

# 想知道改一处会波及哪里 —— 用 --refs
.\qcc_zh_seed.exe --refs srclib_jiayan\qcc_zh.jy > refs.json
```

> 本页第一节那张「5 个巨型函数」表，就是用 `--interface` 的 `line` 字段算出来的（相邻函数定义行号差 ≈ 上一函数的行数）。你也可以自己复算。

## 六、为什么是单文件（设计说明，不是偷懒）

| 理由 | 说明 |
|---|---|
| **自举对账** | 单文件 ⟹ 一份源码对应**一个** SHA256 ⟹ 不动点可逐字节对账。多文件要先拼接再哈希，中间层就多一个不确定源 |
| **无 `#include`** | 甲言不做 `#include`（自包含模式），多文件意味着手工维护拼接顺序 |
| **零依赖分发** | 单文件可被任何一个已知不动点编译器一次编完，不需要构建系统 |

**代价**：可维护性差、diff 噪声大、无法并行开发。
**缓解**：三个 AI 接口 + 本页导航 + 1,443 个特性锚（每改一处先写锚）。

## 七、如果你要改一处，按这个顺序

```
1. --refs 查「谁引用了这个符号」→ 拿到精确行号，不要通读
2. 定位到二节流水线里的对应阶段，只看那一个函数的那一个分支
3. 先在 scripts/feat_zh_*.c 写最小锚（只钉一件事）
4. 验证锚在【旧编译器】上必红 —— 证明它真能抓住这个 bug
5. 改源码，-c 冒烟（几秒）
6. scripts/build_zh.ps1 -NoSeed 跑全链（约 20 分钟，出不动点）
7. scripts/run_tests_zh.py 全量回归
```

> ⚠️ **别用 `-graph` 验 34k 行主源**：它要完整编译，实测超 3 分钟仍不结束（本页整理时踩过这个坑，已改为 `--interface`）。
