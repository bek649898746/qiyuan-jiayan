# jypkg · 甲言包管理器

`jy_pkg.jy`（48.8 KB · 甲言源码）—— **依赖拓扑排序 + 锁文件 + SHA-256 完整性校验**。

> ⚠️ **先说清楚它不是什么**：它**不下载、不解包、不安装**。没有远端注册表、没有网络。
> 它做的是「**读清单 → 求解依赖 → 出锁 → 校验完整性**」，即 `pip-tools` / `cargo` 里**锁文件那一半**。
> `install` 这个子命令名容易误解，按实际能力更接近 `resolve`。

## 编译

源码内包含 `jyjson.jy`（JSON）与 `jylib_sha256.c`（SHA-256），**单文件编译、无外部依赖**。
**必须在它自己的目录里编**（源码用相对包含）：

```powershell
cd tools\jypkg
..\..\qcc_zh_seed.exe jy_pkg.jy -o jy_pkg.exe
# 实测（2026-10-28 · 现役种子）：rc=0 · 1.1 s · 960,976 bytes code
```

## 子命令

```
jy_pkg.exe <清单.json>             # 生成锁文件（= v0.1 兼容形态）
jy_pkg.exe lock   <清单.json>      # 同上
jy_pkg.exe check  <清单.json>      # SHA-256 完整性校验
jy_pkg.exe index  <目录>           # v0.3 扫描包目录 → 生成索引 JSON
jy_pkg.exe select <清单> <索引>     # v0.4 版本约束求解
jy_pkg.exe install <清单> <仓库>    # v0.5 全链：扫仓库 → 约束求解 → 出锁
jy_pkg.exe verify <锁> <仓库>       # v0.7 核锁：锁要求的版本仓库里是否都有
```

中文子命令（`锁` / `校验` / `索引`）在 cmd 下匹配不上 —— Windows 的 argv 是 ANSI(GBK)，源码字面量是 UTF-8。
**命令行请用 ASCII 版**（这条是工具自己打印的说明）。

## 实测状态（2026-10-28 独立复核 · 现役自举种子）

| 子命令 | 判 | 实测 |
|:--|:--|:--|
| `lock` | ✅ **可用** | 拓扑序正确（`liba → libb → app`，依赖在前）；**真幂等** —— 同清单两次 stdout 逐字节一致（245 字符），重定向落盘两次均 313 B 且一致 |
| `check` | ✅ **可用** | SHA-256 三态全对：通过 `rc=0` · 摘要不符 `rc=5` · 文件缺失 `rc=5`（打印期望/实得） |
| `index` | ⚠️ **实验性** | 能扫目录，但**版本恒报 `0.0.0`** —— 不读子目录里的包元数据 |
| `install` | ⚠️ **实验性** | 实测输出**空锁**（依赖 0）—— 它扫的是仓库，不接清单里的依赖 |
| `verify` | ❌ **有缺陷** | ① `lock` 的 stdout 把 JSON 与状态行混在一起 ⟹ 直接重定向出的锁文件 **JSON 非法**（`rc=3`）；② 改用纯净锁后仍报「打不开仓库目录」（`rc=2`），而 `index` 能打开同一目录 |

> **判据的覆盖面就是它的诚实度**：上面「8 条判据」只覆盖 `lock` 与 `check`，
> **8 条全过 ≠ 7 个子命令都能用。**

## 8 条判据（工具自带）

| # | 判据 | 行为 |
|--:|:--|:--|
| ① | 幂等 | 同清单两次运行，锁文件逐字节一致 |
| ② | 拓扑正确 | 每个包的依赖都排在它之前 |
| ③ | 环检测 | 循环依赖 ⟹ 响亮报错、拒绝出锁（`rc=4`） |
| ④ | 缺引用 | 依赖未定义包名 ⟹ 响亮报错、拒绝出锁（`rc=4`） |
| ⑤ | 版本冲突 | 同名包两版本 ⟹ 响亮警告（保留首个 = 确定性，`rc=0`） |
| ⑥ | SHA-256 向量 | 文件内容 `"abc"` 的摘要必须等于 FIPS 180-4 标准向量 |
| ⑦ | 摘要不符 | 篡改 / 摘要错 ⟹ 响亮报错、拒绝通过（`rc=5`） |
| ⑧ | 文件缺失 | 清单声明了文件但不存在 ⟹ 响亮报错（`rc=5`） |

## 清单格式

根对象带 `包` / `版本` / `依赖`，`包表` 是包数组，每项 `名` / `版本` / `依赖` / `文件` / `摘要`：

```json
{
  "包": "app", "版本": "1.0.0", "依赖": ["libb"],
  "包表": [
    {"名": "libb", "版本": "2.0.0",  "依赖": ["liba"]},
    {"名": "liba", "版本": "1.0.0",  "文件": "a.txt", "摘要": "<sha256 hex>"}
  ]
}
```

## 设计要点

**SHA-256 用的是甲言自己的 `jylib` 实现**（源码级包含，连 `<string.h>` 都已剥离、改用自写的 `jy_memcpy_` / `jy_memset_`）
⟹ **包管理器用来校验完整性的密码学，也是甲言自己写的。**

## 已知限制

- 无网络、无远端索引、无解包 —— 见开头
- `index` 不读包元数据 ⟹ 索引里的版本不可信
- `lock` 的 JSON 与状态行混在同一个 stdout ⟹ 想落盘只能自己截取 JSON 段（见上表 `verify` 第 ① 条）
- `verify` 与 `index` 对同一仓库目录行为不一致
