# jyaudit — 甲言产物外部审计器（指令级）

> 用**外部工具链的视角**检查甲言编出的 `.obj`。
> 存在的理由只有一句：**甲言的验证一直闭环在自己内部，而闭环永远测不出 ABI 级缺陷。**

---

## 一、为什么需要这个工具

甲言的日常验证是「自己编译 → 自己链接 → 自己运行」。这套闭环很扎实，但有一个结构性盲区：

> **甲言产物的最终映像基址很低**（`0x400000` 量级）。
> 某些错误的机器码编码 —— 例如把 64 位指针压进 32 位寄存器 —— 在低基址下**恰好仍然合法**（高 32 位本来就是 0，截断无损）。
> **一旦交给 gcc/ld 链接**（基址 `0x140000000`，运行时 `0x7ff6...`），同一段编码立刻非法。

⟹ 甲言**在自己的世界里永远看不到这类缺陷**。

`jyaudit` 就是那面镜子：它不做推理，只报告外部工具链看到的**可观测事实**。

---

## 二、检测项

| 代号 | 检测 | 方法 | 对应后果 |
|:--|:--|:--|:--|
| **[A]** `ADDR32` | 32 位绝对重定位 | `objdump -r` 统计 `IMAGE_REL_AMD64_ADDR32` | gcc/ld **拒绝链接**：`relocation truncated to fit` |
| **[B]** `PTR32` | 32 位寄存器承载/递增 64 位指针 | `objdump -d` 匹配"32 位写入 `%rNd` ⟹ 用 `%rN` 解引用" | **运行时 `0xC0000005`** |
| **[C]** `LINK` | 链接性 | `gcc -shared` 是否接受该 `.obj` | 产物能否被外部消费 |

### [B] 的判定为何要两步

单纯出现 `mov %ecx,%r8d` 是**正常的**（普通 32 位整数运算）。只有当**同一个寄存器随后被当 64 位指针解引用**（`(%r8)`），才说明它承载的是指针 —— 此时 32 位写入就是截断。

工具按此两步匹配，避免误报。

## 三、用法

```powershell
# 抽样 200（默认）扫旧壳资产
powershell -File jyaudit.ps1

# 指定源目录与样本数
powershell -File jyaudit.ps1 -Src D:\.openclaw\workspace\compiler -N 500

# 单文件精查（打印反汇编片段）
powershell -File jyaudit.ps1 -Src C:\path\to\module.c -Verbose

# 全量（数千文件，会跑数小时）
powershell -File jyaudit.ps1 -N 0
```

**参数**

| 参数 | 默认 | 说明 |
|:--|:--|:--|
| `-Src` | `D:\.openclaw\workspace\compiler` | 源文件或目录 |
| `-N` | `200` | 抽样数；`0` = 全部 |
| `-Qcc` | 自动探测 | 甲言编译器路径（优先 `qcc_zh_v2.exe`） |
| `-Work` | `D:\qiyuan_home\jyaudit_build` | **纯 ASCII** 工作区（必须） |
| `-OutDir` | `D:\qiyuan_home\jyaudit_out` | 报告输出 |
| `-Verbose` | 关 | 打印缺陷样本的反汇编片段 |

**输出**

- `jyaudit_report.csv` —— 逐文件明细（判定 / ADDR32 计数 / PTR32 计数 / 链接错误）
- `jyaudit_summary.json` —— 汇总（含编译器 SHA256，便于跨版本对比）

---

## 四、判据与约束

1. **只报事实，不做因果断言**。每条结论都能用 `objdump -r` / `objdump -d` / `gcc -shared` 独立复现。
2. **gcc 作有效性对照**。源本身 gcc 编不过的，判定为 `SRC:源本身gcc不过`，**不归因于甲言**。
3. **必须纯 ASCII 工作区**。甲言**拒收中文路径参数**（实测传入后编译器收到乱码），工具会自动把源复制到 ASCII 工作区。
4. **不修改任何甲言源码**。本工具纯外部观察，与编译器开发互不干扰。
5. **报告带编译器指纹**。`summary.json` 记录编译器的 SHA256，便于对比不同锚定站的结果。

## 五、首轮实测（2026-09-23 · 锚定 `D02FD006`）

| 指标 | 值 |
|:--|:--|
| 样本 | 8 |
| 甲言编过 | 7 |
| 源有效且甲言编过 | 6 |
| **其中 `A:ADDR32阻断链接`** | **6 / 6 = 100 %** |
| `B:PTR32危险模式` | 6 / 6 |
| `C:gcc 拒绝链接` | 6 / 6 |

**⟹ 这不是个例。** 在含字符串字面量的模块上（即几乎所有真实模块），甲言产物的**外部链接成功率当前为 0**。

**为什么此前没有被发现**：甲言的验证闭环在自己内部，`ADDR32` 在低基址下不表现症状；而 `gcc` 是否愿意链接一个 `.obj`，从来不在甲言的验收项里。

## 六、与甲言开发的关系

**本工具不替代编译器开发，也不与其竞争。** 它补的是一个视角：

- **编译器内部视角**（甲言开发者）：知道每一处实现细节、每一张表的容量墙
- **外部使用者视角**（本工具）：看见编译器**看不见自己**的那部分

两者是同一份编译器的**双人复核**，不是重复劳动。
