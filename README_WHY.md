## 一分钟了解

很多人学编程的第一行代码，都必须是英文关键字：`if`、`while`、`return`、`segmentation fault`。

有人说"英文就是编程的普通话"，那就等于说：**想学编程，先过英语这一关**。

甲言做了另一件事：**让关键字、标识符、报错信息全部是中文，同时保持与 C 的兼容** —— 你写 `整 甲 = 1;` 和写 `int 甲 = 1;` 是同一件事，两者可以混写。

但甲言真正想解决的不是"看起来亲切"这件事，而是编译器行业一个更根本的问题：

> **你怎么知道一个编译器没有编错？**

今天所有的编译器，答案都是"跑一下看结果对不对"。这就像**让考官自己出题、自己批卷**。

甲言给出的答案是：**让编译器自己编译自己，然后比哈希。**
把源码交给它，编译出编译器 A；再用 A 编译同一份源码，得到 B；再用 B 编译，得到 C……
**A = B = C，哈希逐字节相同。** 这叫**不动点**。

**改一个字节，哈希就变。任何一个改动的影响，都可以被精确归因。**

这不是营销话术，是**任何人拿这条命令就能复算的事实**。

## 🌟 六个理由

### ① 中文是书写层，不是翻译层

**痛点**：目前市面上的"中文编程"工具，大多数是**预处理翻译器**——你写中文，它翻成英文再交给 gcc。代价是：报错还是英文、调试信息是英文、语法只能跟在英文后面走，**出问题时你面对的是两个世界**。

**甲言的做法**：词法器**直接识别中文词元** —— `若`、`遍`、`返`、`整`、`构`、`枚`、`可空`、`接口` 就是关键字本身。**编译过程里没有"翻成英文再交给 gcc"这一步**；整条自举链也不碰 gcc。

```甲言
构 学生 { 字 姓名[16]; 整 分数; };

整 平均分(构 学生 *表, 整 人数) {
    整 和 = 0; 整 序;
    遍 (序 = 0; 序 < 人数; 序 = 序 + 1) {
        和 = 和 + 表[序].分数;
    }
    返 和 / 人数;
}
```

**收益**：
- **报错也是中文**：`[ERR] 未声明标识符: 局部 '总数'`（不是 `error: 'foo' undeclared`）
- **可以中英混写**：`整`/`int`、`若`/`if` 随时互换 ⟹ 手上的 C 代码能直接进来
- **学习曲线只剩"编程"本身**，不再叠加一层语言关

**证据**：中文关键字 38 个 · 中文标识符 **249,931 处** · 主源 **35,777 行**（`srclib_jiayan/qcc_zh.jy`）

> #### 📌 主源里 30% 是中文，剩下那 70% 到底是什么
>
> 实测（2026-10-26 · 逐字符分类 · 总字符 **2,640,090**）：
>
> | 类别 | 字符数 | 占比 | 性质 |
> |:--|--:|--:|:--|
> | **中文**（汉字 + 中文标点） | 792,632 | **30.02%** | 关键字 / 标识符 / 诊断文本 |
> | 空白（缩进 / 换行） | 891,898 | 33.78% | **任何编程语言都有** |
> | 编程符号 `; , ( ) { } = + - * /` | 621,912 | 23.56% | **全世界通用，不需要中文形态** |
> | **英文字母** | **143,407** | **5.43%** | 见下表 |
> | 数字 | 162,305 | 6.15% | — |
> | 下划线 `_` | 12,414 | 0.47% | — |
> | 其他 | 15,522 | 0.59% | — |
>
> **⟹ 两个容易误读的点：**
>
> 1. **空白 + 符号合计 57.34%** —— 那是**编程语言的骨架**（缩进、换行、`; , ( ) { }`），**跟中英文无关**。它既不是"英文"，也不该翻译成中文。**任何语言的源码都是这个样子。**
> 2. **真正的英文字母只有 5.43%** —— 中文是它的 **5.5 倍**。
>
> **那 5.43% 的英文字母还剩什么**（这是"必须留"的部分）：
>
> | 类别 | 典型例子 | 出现量 | 为什么必须留 |
> |:--|:--|--:|:--|
> | **x86-64 寄存器名** | `rax` `rcx` `rdx` `rsp` `rbp` `eax` `xmm0` … | 约 2,700 次 | **CPU 规格定义的名字**。翻译它 = 和真实硬件脱钩，汇编器生成不出正确字节 |
> | **机器码十六进制** | `0x48` `0x0F` `0x83` … | 3,428 处 | 字节值的**通用表示**；它不是"文字"，是数据 |
> | **C 兼容关键字别名** | `int` `struct` `typedef` `define` … | 约 2,000 次 | **为了让 C 代码能直接进来**：`int 甲 = 1;` 与 `整 甲 = 1;` 完全等价 |
> | **行业专名** | `IR` `token` `tag` `PE` `COFF` `ABI` | 约 700 次 | 中文译法尚未统一，保留**避免歧义** |
> | **系统错误码** | `0xC0000005` | 136 次 | 操作系统的既有事实 |
> | **本项目诊断码 / 编号** | `A9001` `A1001` `R610` `R830` | — | 项目自有编号，便于检索 |
>
> **一句话**：**中文覆盖「语法骨架」（关键字 / 标识符 / 诊断文本）；英文只留在「不可改的外部契约」与「硬件 / 系统规格」处 —— 而那一部分只占 5.43%。**
>
> 运算符与标点（`+ - * / = < > & | ^ ~ ! ? : ; , . -> [ ] { } ( )`）同理：**全世界数学与编程通用，不需要也不应该有中文形态。**
>
> **这条边界不是妥协 —— 恰恰是它能兼容 C 的原因**：符号层保持 C，所以 C 代码能进、ABI 能对上、`.obj` 能互链。

> #### ⚠️ 关于"血统"，我们写在明处
>
> 甲言的主源**不是从零为中文重新设计的**。它的源头是**自家更早的自举编译器 V14**，一路演进来：
>
> | 阶段 | 时间 | 文件 | 规模 | 性质 |
> |:--|:--|:--|--:|:--|
> | **① V14 自举编译器** | **2026-07-13/14** | [`v14_self/`](v14_self/README.md)（源码 + 可执行） | 723 行 → 96 KB | **零依赖自举的起点**：单文件 VM + 汇编器 + 自举 C 子集（28 指令集）。**源码与可执行文件都在仓库里，双击即跑** |
> | ② 编译器演化期 | 07-20 ~ 08-01 | `qcc_min` / `qcc_boot` / `qcc_bare` / `jy_compiler` | — | 从 28 指令 VM 走向真实 x86-64 目标 |
> | ③ 甲言入仓 · C 版信任根 | 2026-08-05 起 | `srclib/qcc_x86.c` | 22,600 行 | 甲言仓内的英文实现，2026-09-06 起停更 |
> | ④ 机械汉化镜像 | — | `srclib_jiayan/qcc_work.jy` | 22,571 行 | 由 C 版逐行机械汉化（中文字符约 5.9%） |
> | ⑤ **手工演进主源（现在）** | 至今 | `srclib_jiayan/qcc_zh.jy` | **35,777 行** | 持续手工加料（中文字符约 30%），全中文标识符 |
>
> ⟹ 所以我们说「**中文书写**」，**不说「中文原生」** —— "原生"容易被理解成"从零为中文设计"，那不是事实。
>
> **但"自举"这件事是从第一天就在的**：V14 已经是一个自举编译器，甲言继承的是这条链，不是从零重新发明。
>
> 我们保证的是一件**可验证**的事：**编译过程里不存在"翻译成英文再交 gcc"这一步**。
> 这一条你可以自己验：把 `gcc` 从 `PATH` 里删掉，整条自举链仍能跑完，且两代产物 SHA256 相同。

### ② 别家的机制缺口，我们实测能补上

**痛点**：每种语言都有自己的"永久缺口"，而且讨论了十几年：

| 语言 | 它缺的东西 | 讨论了多久 |
|:--|:--|:--|
| **Go** | 没有 sum type（代数和类型），漏分支不报错 | 至今没有 |
| **Java** | 没有值类型（Valhalla 项目） | **10 年以上** |
| **Zig** | 没有接口 / trait，只能 comptime 鸭子类型 | 至今没有 |
| **JS / TS** | 没有模式匹配 | TC39 提案多年未落地 |

**甲言的做法**：**把机制当成可枚举的对象来设计**（291 项机制台账），而不是"先写语言、出问题再补"。

**实测（不是宣传）**：

| 能力 | Go | Java | Zig | JS/TS | **甲言** |
|:--|:--:|:--:|:--:|:--:|:--:|
| sum type（带载荷枚） | ✗ | ✗ | ✗ | ✗ | **✅** |
| 值语义（结构体复制） | ✗ | ✗ | ✓ | ✗ | **✅** |
| 接口 / trait | ✓ | ✓ | ✗ | ✓ | **✅** |
| 模式匹配（择） | ✓* | ✓* | ✓ | ✗ | **✅** |
| 真泛型单态化 | ✓（1.18+） | ✓ | ✓ | ✓ | **✅** |
| 可空类型 + 判空 | ✗ | ✗ | ✓ | ✓ | **✅** |
| **扩展方法** | ✗ | ✗ | ✗ | ✗ | **✅** |

> 注：※ Go/Java 的 `switch` 有穷尽性检查，但**没有 sum type 的载荷与类型安全**。

**收益**：
- **一次学，多家的好机制都有**（而且都在同一套语法里，不用切项目）
- **机制可以互相咬合**（实测：接口 × 扩展方法 × 泛型 三者可互相调用）
- **中文命名让机制更好记**：`可空`、`判空`、`枚`、`择`、`接口`、`实现`、`扩展`

### ③ 15 MB，clone 即用，不需要装任何东西

**痛点**：装一个 C/C++ 工具链是什么体验？—— 下载几个 GB、配环境变量、版本不匹配、`MSVC` / `MinGW` / `clang` 三套打架、离线环境直接卡死。

**甲言的做法**：**仓库自带一个 15 MB 的种子编译器 `qcc_zh_seed.exe`**。

```powershell
git clone <仓库>
cd <仓库>
.\qcc_zh_seed.exe 你的程序.jy -o 你的程序.exe
.\你的程序.exe
```

**不需要 gcc、不需要 Python、不需要联网、不需要管理员权限。**

**收益**：
- **离线可用**（内网、保密环境、飞机上都能写）
- **无版本地狱**（就一个 exe，不会"昨天能跑今天不行"）
- **分发简单**（把 exe 拷过去就能用）

**证据**：把 `gcc` 与 `g++` 从 `PATH` 完全移除后，`qcc_zh_seed.exe` 仍能编译并运行成功，且两代产物 SHA256 完全相同 —— **纯自闭环成立**。

### ④ 任何人都能验证它没有编错

**痛点**：用一个小众编译器，最怕的是"它编出来的东西对不对我不知道"。换成商业编译器也不解决——你依然得相信它。

**甲言的做法**：**把验证做成可复算的公开事实**。

| 验证方式 | 命令 | 时间 |
|:--|:--|:--|
| **30 秒自证**（8 项：编译器自检 / 编译运行 / 中文关键字 / 代码图谱 / 结构化诊断） | `powershell -File scripts/verify_90s.ps1` | **3 秒** |
| **九条语言线**（用甲言写的 9 种语言实现，可编译可运行） | `powershell -File scripts/verify_multilang.ps1` | **7 秒** |

**收益**：
- **不信我们，跑一条命令**：全部判据都是"输出必须等于什么"，不是"看起来对"
- **可审计**：每个测试锚都写明了期望输出/退出码，用 `@EXPECTED` 标注

### ⑤ 连开发者工具，也是甲言自己写的

**痛点**：多数"自举语言"的自举只做到编译器为止——编译器能编译自己，就算交差。但**开发者每天真正在用的东西**（编辑器插件、语言服务器、包管理器）没人做 ⟹ 语言只能"能编译"，不能"能开发"。

**甲言的做法**：把这三样也用甲言写。

| 工具 | 规模 | 能力 |
|:--|--:|:--|
| **包管理器 `jypkg`** | **48.8 KB 甲言** | 版本约束求解 · **SHA-256 完整性校验（校验用的密码学也是甲言自己写的）** · 依赖拓扑序 · 环检测 · 7 条判据 |
| **LSP 语言服务器 `jylsp`** | **42 KB 甲言** | 补全 · 跳转 · 跨文件 · **中文路径跳转** · 诊断转发（+ 6 个配套工具） |
| **VSCode 扩展 `vscode-jiayan`** | 8 文件 | 语法高亮 + 编译 / 显示诊断 / 重启语言服务 三条命令 |

**收益**：
- **写完代码立刻有编辑器支持**：高亮、补全、跳转、诊断全中文
- **包管理器不依赖外部生态**：完整性校验走自己的 SHA-256，不引第三方库
- **一次修在工具里，所有项目受益**

**证据（只有真做才会撞到的问题）**：
写 LSP 时发现 **甲言产物不跑 CRT 标准流初始化 ⟹ `stdin` / `stdout` / `stderr` 三个 `FILE*` 全为 NULL**，最终改用 `GetStdHandle(-10)` + `ReadFile` 直读。**这类经验，只有真的用这门语言去实现一个协议服务器才拿得到。**

### ⑥ 想试一种语言的表达力，用甲言写

**痛点**：验证「某种语言机制到底成不成立」，通常要付三种代价 —— **装它的工具链、搭环境、等运行期才发现错**。而这些机制很多是**编译期**行为（类型检查、不可变绑定、运算符按类型分派），运行期观察不到，只能靠编译器本身来验。

**甲言的做法**：**直接写一个最小内核**（不是写解释器，是把机制本身实现出来），编译期就知道成不成立。

**九种语言各自「最不能替代」的那个机制，都能写出来并跑通：**

| 线 | 压的机制 | 为什么这一点换不掉 |
|:--|:--|:--|
| JS | 表达式优先级 + 递归下降求值 | 优先级是**语法层**的事 |
| JVM | **零地址栈式字节码**（操作数栈 + 局部变量表）| 指令**不带目标槽** ⟹ 与三地址码是两种计算模型 |
| Java | **Java 源码 → JVM 字节码 → 执行** | 是**编译器**不是解释器；栈机好处：后序边编边发，**无需寄存器分配** |
| C++ | **`<<` 的双重身份** —— 靠左操作数类型分家 | `cout << x` 流插入、`a << b` 左移 ⟹ **运算符重载的核心：解析由类型驱动** |
| C# | **RAII** —— 作用域退出自动调析构 | 资源管理与作用域绑定 |
| Go | **`:=` 短声明** vs **`var x int`**（类型后置）| 语义分界：`:=` 是声明（可新建）、`=` 是赋值（须已声明）|
| Python | **缩进感知词法**（发 `INDENT`/`DEDENT`）| 块由缩进决定，与花括号是**两种语法范式** |
| Rust | **`let` 默认不可变**（对不可变绑定赋值 = 编译期报错）| Rust 招牌语义，且是**编译期**行为 |
| TypeScript | **编译期静态类型检查**（不符就报错，不生成码）| 前六条压运行期，这条压**编译期** |

**实测（2026-10-26 实跑，可复算）**：
- **入口验证**：`scripts/verify_multilang.ps1` ⟹ **9/9 条线编译并运行成功 / 7.2 秒**
- **全量双向判据**：`scripts/verify_multilang_full.ps1` ⟹ **72 正例全过 + 13 期望失败全确认 / 64.4 秒**
  （13 个"期望失败"不是允许失败，是**判据要求它们必须报错**：4 个故意负例验证关键字保护/未声明检测，9 个历史旧版留痕）

**这四样都能在甲言里直接落地，因为它们在编译期就能被验证：**

| 想试的机制 | 在甲言里怎么落地 |
|:--|:--|
| 「不可变绑定，赋值即编译期报错」 | `常` + 编译期检查 |
| 「类型不符就不生成码」 | 编译期类型检查（类型编码 0/1/2/3）|
| 「同一符号按类型分家」 | 类型驱动的运算符解析（`<<` 双重身份已实现）|
| 「零地址栈机」 | 栈机就是产物本身 |

> **一句话**：**编译期就能验证「这种语言机制成不成立」，不用等运行到那一行才发现。**

**⚠️ 定位说明**：`examples/multilang/` 的九条线是**语言机制验证集，不是可用实现** —— 没有 CLI 外壳、不读文件、不接受 argv。
它们的价值是「**中文能不能承载编译器级抽象**」，不是「做九个可用的语言工具」。

**怎么自己验**：
```powershell
powershell -ExecutionPolicy Bypass -File scripts/verify_multilang.ps1        # 7 秒
powershell -ExecutionPolicy Bypass -File scripts/verify_multilang_full.ps1   # 64 秒
```

| **编程入门教学**（中文母语者） | 母语即语法，报错也是中文 ⟹ 只专注"编程概念" |
| **需要离线 / 内网 / 保密环境** | 15 MB 零依赖，拷过去就能编 |
| **想理解编译器怎么工作** | 3.5 万行、中文标识符、可自举、可调试 —— 比读 GCC 现实得多 |
| **需要"可验证构建"的场景** | 不动点哈希 ⟹ 产物可归因、可复现 |

| **想验证某种语言机制能不能成立** | 直接写最小内核，**编译期**就知道成不成立；九种语言的辨识性机制已实测 **9/9**（见上文 ⑥）|
| **想给中文生态做工具链** | ABI 兼容 Win64，可链接 C 的 `.obj` 与静态库 |

### ⚠️ 使用前请确认这几条边界

| 边界 | 说明 |
|:--|:--|
| **不是 C++ 编译器** | 只兼容 C（含部分 C11）。**真正的 C++ 源文件编不了** —— 实测 9 项 C++ 独有语法，**8 项直接报错**（`class` / `namespace` / `template` / `std::cout` / `new`·`delete` / `bool`·`true` / 构造函数 / 按类型重载），仅 `int&` 引用能编过但运行结果不对。<br>⚠️ **别与下面这件事混淆**：仓库 `examples/multilang/cpp/` 里的「C++ 12/12 · 100%」，指的是**用甲言写的 12 个 C++ 风格程序全部编译通过**，**不是「支持 C++ 语言」**。 |
| **暂无优化器** | 直译式码生成 ⟹ 产物体积与运行性能**不及 GCC**；编译速度见下方数据。 |
| **目前主要面向 Windows x64** | 产物为标准 PE；其它平台尚在规划。 |
| **项目处于快速迭代期** | 仍在日更，API 与行为可能调整。**已知问题见 [KNOWN_ISSUES_v1.0.md](KNOWN_ISSUES_v1.0.md)**（持续公开登记）。 |
| **第三方包生态尚在早期** | 已有**自建包管理器 `jypkg`**（版本约束求解 / SHA-256 完整性 / 拓扑序 / 环检测）与 **VSCode 扩展 + LSP 语言服务器**；但**公共包仓库尚在少量试水**，绝大多数第三方 C 库仍走标准 C 库。 |

# 1. 拿仓库（自带编译器，不需要装任何东西）
git clone <仓库地址>
cd qiyuan-jiayan

# 2. 写一个程序：hello.jy
#    整 主() { 输出("你好，世界\n", 0); 返 0; }

# 3. 编译 + 运行
.\qcc_zh_seed.exe hello.jy -o hello.exe
.\hello.exe

powershell -File scripts/verify_90s.ps1
