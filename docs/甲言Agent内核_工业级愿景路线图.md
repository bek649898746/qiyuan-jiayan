# 阶段 0：地基攻坚（v0.x → v1.0 的前置，新增）

> v1.1 关键修订：v1.0 的 H1==H2 闭环有三个硬前置，全部在今天得到实证或明确路径。

## 0.1 数据面解阻（NVMe 读写回环）

### 现状（2026-08-08 实证）
- ✅ PCIe枚举 / MMIO / 控制器启用 / Identify（SN=JIAYAN 读回）
- ✅ Tensor池 v2 内存层（版本链+追加写）TENSOR-PASS
- 🔧 读写回环被 QEMU/GRUB 时序锁住：GRUB 启动异步读盘产生残留完成，污染完成检测
- 三条铁律已固话：**NVM 读写必须走 I/O 队列（非管理队列）/ bin 模式零全局 / 命令计数器**

### 解阻路径
- 独特CID + 全CQ扫描完成检测（免疫GRUB残留，已实现待调）
- 或干净队列环境（QEMU启动顺序/GRUB不碰NVMe）
- 工作量：~300行 | 1-2天

## 0.2 探针 → 模块化重构

### 现状（镜子审计）
- 31 个独立内核探针（v5..v37），串口驱动复制 31 份
- 2 万行的前提是模块化，否则=2 万个复制粘贴探针

### 目标结构
```
srclib/kernel/
  serial.c   pci.c    nvme.c    tensor.c
  sched.c    mem.c    net.c     gpu.c
```
- 每个模块一个真实现（宿主+镜像双版本），探针全部退役
- 工作量：~800行 | 2-3天

## 0.3 镜像解冻（H1==H2 的前提，v1.1 最大修订）

### 实证结论（2026-08-08 三组实验推翻"冻结"）
| 同步项 | 结果 |
|:--|:--|
| 字节映射（lexer） | ✅ OK（74MB 自举成功） |
| is_short / decl short | ✅ OK |
| case 12/10 + 11 处 short 分支 | ✅ OK（自举成功） |
| __attribute__ 吞掉 | ❌ 破坏自举（控制流结构触发禁点，待改实现） |
| pesz 数组（全局新增） | ❌ 全局区禁点（需替代方案） |

**真相**：镜像对"插入位置"敏感（全局区 1-98 / per-node 区 / 特定函数边界是禁点），函数内安全点的修改可同步。**"任何修改都崩"是早期在禁点测试的错误结论。**

### 解冻路径
- 可同步项：字节/短/宽度分支 → 立即同步，产生**新不动点**
- __attribute__：改用无 continue/break 的简单实现或换位置
- pesz 宽度机制：复用已有 per-node 数组备用位，或动态分配指针找安全声明点
- 验证：v1==v2==v3 新不动点 + 不动点测试套件
- 工作量：~1-2天（可同步项） + 1-2天（pesz/attr 攻关）
