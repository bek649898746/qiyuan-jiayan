> 每条线压的是那个语言**最有辨识度的机制**（不是把 C 语法换个壳）。

> ### ⚠️ 定位：语言机制验证集，不是可用实现
>
> | 它**是** | 它**不是** |

### 剩下 10 个为什么不过（全部有明确根因）

| 根因 | 数量 | 文件 | 说明 |
|:--|--:|:--|:--|
| **甲言关键字表演进**：`跳` 现为跳转语句保留字 | **7** | `java/kw1.c` `min2/3/5/6/11/15.c` | 这些 10-11 的文件把 `跳` 当变量名用；现在词法器把它当关键字节点了 ⟹ `A9001 关键字 '跳' 不能作赋值目标` |
| **甲言关键字表演进**：`短` 现为类型词 | 1 | `csharp/cs9.c` | 形参名 `短` 与类型词冲突 ⟹ `A9001` |
| 源文件自身括号错 | 1 | `java/min4.c` | `多余右括号 '}' 行 158` —— 这是**文件本身的 bug**，不是编译器问题 |
| `串长` 内建限制 | 1 | `js/jsl7.c` | `串长` 只适用原生串（带 4 字节长度前缀），对普通 `字` 缓冲不适用 |

> **这 8 个「关键字冲突」不修，原样保留。**
> 它们是「**甲言的语言在演进、而且变严了**」的活证据。想验证可以自己改个名（`跳` → `跳位`）再编，会立刻通过 —— 但我们不做，因为改了就没证据了。

### 为什么会撞词 —— 这不是随意加限制，是一次刻意修复

| 项 | 内容 |
|:--|:--|
| **机制** | `qcc_zh.jy` **L7766** `若 (!比较字符串(串值, "跳")) 返 大于;` ⟹ `跳` 被词法器改写为**跳转语句关键字 token**；**L7771** 同理把 `短` 改写为**类型词 token** |
| **引入** | 提交 **`f6ce808a`** · **2026-10-05 17:49** · 作者 郑宇和 · 第455站第八十八轮 · commit message：「语句关键字 **撞词硬收**（跳/断/续/循环/若/否/返/遍/择/例/缺/做 ⟹ A9001）」 |
| **为什么** | 撞词会导致**静默崩溃**：`跳 = 1;` 被当成跳转语句 ⟹ `=` 与右值**被静默丢弃** ⟹ 生成跳转到不存在的标签 ⟹ **运行期 `0xC0000005`** |

编译器自己的报错把因果写得最清楚：

```text
[ERR] A9001 关键字 '跳' 不能 作 赋值目标 —— `跳` 是 **跳转 语句关键字**,
词法器 已 改写为 token ⟹ `跳 = 1;` 被 当 跳转语句, 等号 与 右值 **被 静默 丢弃**,
且 生成 跳转 到 不存在 的 标签 (运行期 0xC0000005)
```

**⟹ 10-05 那次不是随手加限制，是把一个「运行期静默崩溃」换成「编译期响亮报错」。**
所以这 7 个 java 文件在 10-05 之前，**就算能编过，跑起来也是崩的** —— 硬收之后它们从「能编但会崩」变成「编不过」，这是升级。

具体撞词点：`java/min2.c` L373–391 共 **12 处 `跳 = 1;`**（`跳` 用作"是否跳转指令"的标志变量）；`csharp/cs9.c` L5 形参名 `短`。

### 修复过程（14 个文件，各 3 行，零语义改动）

首轮压测有 25 个失败，其中 **14 个是同一个根因**：`A1001 全局 '栈顶' 在其声明之前被写`。
处理方式与第三节那 3 个入口文件相同 —— 把 3 行 VM 声明前移到 `编源()` 前向声明之前。
修完 14/14 全部通过，运行输出正确（`CPP-C3 函数 + 重载决议`、`GO-G4 struct 与字段访问`、`PY-P4 函数 def/调用`、`RS-R4 struct + impl 方法`、`TS-T4 interface + 结构化类型检查`…）。

### ⚠️ 一个必须记下的坑

`rust/否链2.c` **编译 rc=0，但运行起来是死循环**（5 秒超时被强杀）。
它是首轮压测把我卡住 10 分钟的元凶——**因为脚本在编译成功后会直接运行产物，没有超时保护**。

**教训**：查「某种语言的源码」时，**不能用扩展名当判据**——尤其当这门语言兼容 C、源码就存成 `.c` 的时候。要用**内容特征**（这门语言独有的关键字/语法）。
