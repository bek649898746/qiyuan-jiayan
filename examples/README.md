# examples/ — 示例程序目录

**这里有两个方向相反的类别。先看这一页，能省你一次困惑。**

| 类别 | 数量 | 编译结果 |
|:--|--:|:--|
| **① 正例** —— 能编译、能运行 | **9 个** | 成功 |
| **② 反例** —— 文件名带 `neg_` | **7 个** | **故意失败** |

> ⚠️ **`neg_` 开头的 7 个文件编译一定会失败。这不是 bug，是设计。**
>
> 它们演示的是**甲言的静态检查能抓住什么错**——每一份都对应一个具体诊断码（`A3001` / `A6090` / `A6016` / `A8001`）。
> 如果你第一次来、只想看它能不能跑，**请先看下面「推荐顺序」的第一行**。

---

## 一、正例（9 个，能编译能跑）

| 文件 | 演示什么 |
|:--|:--|
| **`hello.jy`** | 最小可运行程序 —— 中文关键字 + 标准 C 库混写 |
| **`成绩.jy`** | 学生成绩管理（单文件）—— 中文命名 + 结构的实际项目形态 |
| `combo_c_modern.jy` | C 库直接进安全体系：`strstr` 返回的 NULL 就是甲言的「可空」—— 零包装、零分配 |
| `static_guards.jy` | 三件事：C 和 Go 都会放过，甲言编译不过（静态检查的边界演示） |
| `ok_borrow.jy` | 借用的**正确**写法 —— 与 `neg_borrow.jy` 成对，对照看最清楚 |
| `concurrency.jy` | 线程是**编译器内建**的（`线程 t 跑 f, n`），不需要自己实现运行时 |
| `channel_mt.jy` | 跨线程通道：两个线程经同一个通道传 100 个数，满时阻塞、有消费者则唤醒 |
| `evaluator.jy` | 表达式求值器 —— 完整优先级链 10 层，约 250 行 |
| `stress_csv.jy` | 压力测试用（CSV 解析），文件较大 |

## 二、反例（7 个，**故意编译失败**）

| 文件 | 期望诊断码 | 演示的检查 |
|:--|:--|:--|
| `neg_borrow.jy` | **A3001** | 借用期内写 —— NLL 借用检查 |
| `neg_borrow2.jy` | **A3001** | 借用三件套：借用声明 + 取地址绑定 + 借用期内写 |
| `neg_dataflow.jy` | **A6090** | 数据流变量的二次赋值 |
| `neg_dataflow2.jy` | **A6090** | 同族的另一形态 |
| `neg_exhaustive.jy` | **A6016** | 漏分支 —— 模式匹配非穷尽 |
| `neg_exhaustive2.jy` | **A6016** | 同族的另一形态 |
| `neg_nullable.jy` | **A8001** | 可空类型未判空就解包 |

**⟹ 这 7 个的价值：它们证明「错误会在编译期被拦住，而不是运行时崩掉」。**
跑这些时，看的是**报什么错、错在哪个码**，不是「能不能跑通」。

## 三、怎么跑

编译器就在仓库根目录，**零依赖、不需要 gcc**：

```powershell
# 正例
.\qcc_zh_seed.exe examples\hello.jy -o hello.exe
.\hello.exe

# 反例（预期失败，重点是看错误码）
.\qcc_zh_seed.exe examples\neg_borrow.jy -o x.exe
# → [ERR] A3001 借用检查 (NLL)：变量 x 被引用 r2 借用中
```

## 四、推荐顺序（第一次来 / 教学场景）

| 步 | 做什么 | 为什么 |
|--:|:--|:--|
| 1 | `hello.jy` | 确认工具链能跑，30 秒内看到输出 |
| 2 | `成绩.jy` | 看一个真实小项目的形态（中文命名、结构、流程） |
| 3 | `ok_borrow.jy` → `neg_borrow.jy` | **成对看**：先看合法写法，再看它挡住的错误写法 |
| 4 | `static_guards.jy` | 理解「C 和 Go 放过、甲言拦住」这条边界在哪 |
| 5 | `evaluator.jy` | 想看深度时读这个（10 层优先级链） |
| 6 | `concurrency.jy` / `channel_mt.jy` | 并发原语是语言级的，不是库 |

**⟹ 教学上最有说服力的一对是第 3 步**：同一份逻辑，一个过、一个被拦，并排看得见。

## 五、两个常见困惑

**Q：为什么 `neg_*.jy` 编译不过？是我环境坏了？**
A：不是。文件名 `neg_` 就是「negative case」的标记，编译失败是它的**预期行为**。看错误码对不对得上第二节的表格。

**Q：为什么 `examples/` 里没有更大更完整的项目？**
A：有，但不在这个目录 —— 仓库里最大的「示例」是编译器**自己**（`srclib_jiayan/qcc_zh.jy`，约 3.8 万行）。它编译自己两次，产物哈希必须相等，这是比任何 demo 都硬的证明。详见根目录 `README.md`。
