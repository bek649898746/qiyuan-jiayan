## 一分钟了解

一个 AI 改代码的循环是这样的：

```
改 → 编译 → 读报错 → 再改
```

在这个循环里，AI 站在一个很特殊的位置：**它会自我修正，但它读不到你的言外之意。**

人遇到 `error: expected ';' before '}'`，心里会自动补一句"大概是上一行漏了分号"——**这个"大概"来自经验、直觉、和对整个项目的印象**。

AI 读到的是一模一样的这行字，但它的全部世界就是这几行输出。**输出里没有的，它不知道；输出里含糊的，它只能猜。**

所以「为 AI 设计」不是给编译器加个接口、加个插件、加个 MCP 服务。它要重新回答一个问题：

> **当一个使用者没有直觉、不能读言外之意、必须靠可验证的信号工作时，
> 一个编译器应该长什么样？**

甲言的答案只有三句话：

| 它需要什么 | 甲言怎么做 | 一句话 |
|:--|:--|:--|
| **说清楚** | 报错带编号、原因、位置；可切结构化输出 | 不让它猜 |
| **不撒谎** | 危险的东西编译期就拦，不留到运行期 | 不让它错得无声无息 |
| **能复现** | 每个阶段可导出、可重放、可哈希对账 | 让它能自己查自己 |

## 🌟 为什么「为 AI 设计」不是营销词

**人能容忍的事，AI 容忍不了。** 这是整份文档的出发点：

| 人能容忍 | 为什么 AI 不能 |
|:--|:--|
| 报错含糊，自己去翻文档 | AI 读不到文档的「言外之意」，它只有报错文本 |
| 「编译过了但结果不对」，然后靠直觉排查 | AI 没有直觉，它必须靠可观测状态定位 |
| 编译偶尔不确定 | AI 无法验证自己的改动是否真的生效 |
| 出错后人工复现一次 | AI 需要能重放每一个阶段 |

**反过来，AI 比人强的地方也改变了设计取舍：**
它不在乎关键字是不是英文，不在乎语法甜不甜，不在乎 IDE 补全。
**它只在乎：我改的这一行，有没有真的生效；如果错了，错在哪、为什么。**

## 🧭 五件事，每件都能自己验

> 下面每条都给了命令。**不要信本文，跑一遍。**
> 数字故意不写死 —— 用命令自己数（口径见 [数据口径与核验方法](manual/数据口径与核验方法.md)）。

### 一 · 说得清 —— 报错是一份文件，不是一句话

```powershell
.\qcc_zh_seed.exe --diagnostics=json 你的程序.c
.\qcc_zh_seed.exe --dj            你的程序.c   # 同一件事，短别名
```

每条诊断带**错误码 + 位置 + 原因**。错误码是稳定的编号，不是自然语言 ——
`A` 开头的码表在仓库 `error_codes/` 下，**同一个码永远指同一类失败**，跨版本不变。

```powershell
# 自己数有多少个码（不要信文档里的数字，第二天就可能过时）
(Select-String -Path srclib_jiayan\qcc_zh.jy -Pattern '"[A-Z]\d{4}"' -AllMatches |
  ForEach-Object { $_.Matches } | ForEach-Object { $_.Value } | Sort-Object -Unique).Count
```

**为什么这对 AI 重要**：AI 可以按码写规则（"见到表示隐式窄化的那个码，就补一次显式转换"），
而不必去解析自然语言。**码是接口，话是注释。**

> ⚠️ **诚实边界**：`--diagnostics=json` **尚未覆盖全部检查点**。
> 部分早期检查仍只输出纯文本 `[ERR]`。
> AI 端的容错判据：输出以 `{"diagnostics"` 开头 → 按 JSON 解析；以 `[ERR]` 开头 → 按正则提取。

### 二 · 拦得住 —— 危险的东西编译期就拦

甲言与 C 语法兼容，但**不加显式意图就不放行**：

```powershell
# 危险写法会被编译期拒绝，而不是留到运行期崩
.\qcc_zh_seed.exe 一个会崩的.c      # 期望：非零退出 + 明确错误码
```

覆盖的类别包括：隐式窄化转换、整数溢出、空指针解引用、所有权/借用违规、越界常量下标。
每条都能单独关掉（用于兼容第三方 C 代码），见 `--lenient` 与下文 QCC 开关。

**为什么这对 AI 重要**：**AI 最常犯的错是"看起来对"**。
编译期拦住，等于把这个错误的反馈时间从"运行时偶发崩溃"提前到"编译时就红"。

### 三 · 证得明 —— 编译器自己证明自己没错

这是甲言最不常见的一件事：

> **你怎么知道一个编译器没有编错？**

通行答案是"跑一下看结果对不对"—— 那等于**让考官自己出题、自己批卷**。

甲言的答案是 **不动点**：

```powershell
powershell -File scripts/build_zh.ps1
# 判据：连续两代产物 SHA256 完全相等（v1 == v2 == $expected）
```

但它**不够**，甲言自己也承认这一点：

> **不动点收敛 ≠ 正确。一个错误的编译器，可以稳定地产生同样的错误。**

所以真正的准确性判据是**独立语料**：

```powershell
python scripts\run_tests_zh.py --zh-feat
# 判据：行为断言全绿。个数以脚本输出为准，不要信任何写死的数字
```

**三道判据合起来才算数**：

| 判据 | 防什么 |
|:--|:--|
| **自举不动点** | 防**漂移**（"改坏了却没人发现"）|
| **独立语料（行为断言）** | 防**错误**（"稳定地错"）|
| **GCC 对照** | 防**自洽地错**（"自己跟自己对得上，但都不对"）|

### 四 · 复得出 —— 每个阶段都能导出和重放

```powershell
.\qcc_zh_seed.exe --dag 产物.json          你的程序.c   # 阶段哈希链
.\qcc_zh_seed.exe --checkpoint 现场.txt    你的程序.c   # 崩溃尸检点
.\qcc_zh_seed.exe --recorder 黑匣子.txt    你的程序.c   # 编译黑匣子
.\qcc_zh_seed.exe -graph 图谱.json         你的程序.c   # 代码知识图谱
```

> ⚠️ **参数顺序会咬人**（实测踩过）：
> `-graph 图谱.json 源文件.c` ✅ 正确
> `-graph 源文件.c` ❌ 会把**源文件本身**覆盖成 JSON
> **凡是接受输出路径的参数，都放在源文件之前，并且先确认路径。**

**为什么这对 AI 重要**：AI 不能靠"我觉得刚才好像改对了"。
它需要**把一次编译的每个阶段钉成哈希**，然后对比两次编译哪一步开始不一样 —— 这叫可归因。

### 五 · 看得见 —— 内部状态可查

```powershell
# 先列出真正的开关清单（不要信文档里的个数）
(Select-String -Path srclib_jiayan\qcc_zh.jy -Pattern 'QCC_[A-Z_0-9]+' -AllMatches |
  ForEach-Object { $_.Matches } | ForEach-Object { $_.Value } | Sort-Object -Unique)
```

这些 `QCC_*` 环境变量打开后，可以把词法、符号表、IR、码生成内部状态打到错误流。
**用途只有一个：出问题时，让 AI 能看到编译器内部，而不是对着结果猜。**

> ⚠️ **诚实边界**：`--help` 目前**没有列出**这些开关。
> 它们是"存在但未自我介绍"的能力。本文档与 [AI 快速上手](manual/AI快速上手.md) 是它们第一次成文。

## 📊 我们做到哪了（如实）

一份能力自评，**排序本身就是设计决策**：

| 维度 | 状态 | 依据 |
|:--|:--|:--|
| **可信**（正确性 / 确定性） | ✅ **已完成** | 自举不动点 + 独立语料全绿 + GCC 对照 |
| **可知**（可观测 / 可解释） | ✅ **能力齐全，文档在补** | 错误码表 + `--diagnostics=json` + `QCC_*` 开关；缺口见上文两处"诚实边界" |
| **可用**（迭代速度） | ⚠️ **第三优先级，正在补** | 见下 |
| **显式特性** | ⚠️ 部分未在自举源码中大量使用 | 契约后置条件 / 不变式 / 静态断言等设计已完成，实际用量待提升 |

### 🔴 关于「快」这件我们还没做好的事

**甲言当前的编译速度不是它的强项，如实说明。**

- 现状：`--cache` 是**文件级**哈希缓存（源码变一个字节即全量重编），不是真正的增量编译
- 计划：码生成是函数粒度的，理论上可下沉为函数级增量；**尚未实现**
- 排序理由：

> **AI 编译器必须先「可信」，再「可知」，最后才谈「快」。**
> **在一个不可信的编译器上做性能，等于更快地出错。**

这个排序是我们刻意的，不是遗漏。

## 这条路线适合谁 / 不适合谁

| 适合 | 不适合 |
|:--|:--|
| 要让 **AI 反复改、反复编、反复验**的项目 | 追求**编译速度**到极致的场景（见上文"快"）|
| 把**编译器输出当接口**来编程的系统（按错误码写规则）| 只想要"能编过就行"的宽松 C 兼容 |
| 需要**审计、复现、归因**的场合 | 只需要一次性编译、不需要复现的场景 |
